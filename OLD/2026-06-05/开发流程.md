# 开发流程规范

> **目标**: 确保每次 AI 会话的工作可追溯、可延续。核心原则：**改代码必改文档**。

---

## 1. 文件分类

### 🟢 持续维护（改代码后必须同步更新）

| 文件 | 何时更新 | 更新内容 |
|---|---|---|
| `文档/功能状态.md` | 完成/新增功能 | 改状态标记 + 备注 |
| `文档/版本记录.md` | 发布/修 Bug/合并 PR | 新版本号 + 变更项 + Bug 修复 |
| `文档/数据结构.md` | 修改 Schema | 更新表结构 + 新增/解决已知问题 |
| `文档/系统设计.md` | 功能行为实质变化 | 更新对应功能模块描述 |
| `文档/AI操作手册.md` | 技术栈变更、新文件、编码规范变化 | 更新对应章节 |

### 🟡 按需更新

| 文件 | 何时更新 |
|---|---|
| `文档/开发流程.md`（本文件） | 流程本身调整时 |

### 🔴 禁止手动编辑

| 文件/目录 | 原因 |
|---|---|
| `src/generated/prisma/` | Prisma 自动生成 |
| `.next/` | Next.js 构建输出 |
| `node_modules/` | npm 管理 |
| `package-lock.json` | npm 管理 |
| `dev.db` | SQLite 数据库，通过 Prisma 操作 |
| `tsconfig.tsbuildinfo` | TypeScript 增量编译缓存 |

## 2. 标准任务流程

### 2.1 任务开始前

```
[ ] 1. 阅读 文档/功能状态.md — 确认要做的功能当前状态
[ ] 2. 阅读 文档/数据结构.md — 确认是否有已知问题影响本次任务
[ ] 3. 涉及 Schema 变更时，先查阅数据结构的优化路线图
[ ] 4. 启动 dev server，验证系统正常运行
```

### 2.2 编码过程中

```
[ ] 1. 只改与任务直接相关的文件（外科手术式修改）
[ ] 2. 不在本次改动中顺手"优化"无关代码
[ ] 3. 涉及数据模型变更:
     a. 先改 prisma/schema.prisma
     b. 运行 npx prisma migrate dev --name "描述"
     c. 更新 文档/数据结构.md
     d. 按需更新 seed.ts
[ ] 4. 涉及 API 变更时，确保前后端类型一致
[ ] 5. 涉及 LLM Prompt 变更时，记录改动原因到版本记录
```

### 2.3 任务完成后

```
[ ] 1. 验证功能可跑通（浏览器手动测试 + 控制台无报错）
[ ] 2. 更新 文档/功能状态.md — 标记完成状态
[ ] 3. 更新 文档/版本记录.md — 记录变更内容
[ ] 4. 改了数据模型 → 更新 文档/数据结构.md
[ ] 5. 改了功能行为 → 更新 文档/系统设计.md 对应章节
[ ] 6. 改了技术栈/项目结构/编码规范 → 更新 文档/AI操作手册.md
[ ] 7. git 提交，commit message 遵循格式
```

## 3. Commit Message 规范

```
格式: [类型] 功能模块: 简短描述

类型: feat / fix / refactor / doc / chore

示例:
  [feat] quick-score: 新增评分历史覆盖提示
  [fix] parser: LLM JSON 解析增加 token 截断检测
  [refactor] attendance: D 分数重算逻辑抽为独立工具函数
  [doc] 文档体系重构，消除交叉重复
  [chore] 升级 prisma 到 7.9.0
```

## 5. 新 AI 会话启动

```
第 1 步: 读 文档/AI操作手册.md → 项目全景
第 2 步: 读 文档/功能状态.md → 当前进度
第 3 步: 读 文档/开发流程.md → 本文档
第 4 步: 根据任务需要查阅 系统设计.md / 数据结构.md
第 5 步: npm run dev 验证系统可运行
第 6 步: 开始工作
第 7 步: 完成后按 §2.3 更新文档
```
