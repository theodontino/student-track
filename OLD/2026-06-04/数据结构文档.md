# 数据结构文档

> **用途**: 记录当前数据模型、已知问题、优化方向，供后续重构参考。  
> **数据库**: SQLite (libsql)，通过 Prisma 7 ORM 管理  
> **Schema 文件**: `chem-track-ai/prisma/schema.prisma`

---

## 1. 当前 ER 关系

```
Semester 1 ────< ClassSession N ────< Attendance N >──── Student 1
              │                    ───< DailyMetric N                │
              └──< DailyMetric N (v0.4)                              │
Student 1 ────< Event N ──── ClassSession 1
Student 1 ────< Communication N ──── ClassSession 1                │
                                                                     │
DraftRecord (独立表，与 Student 无外键关联，解析结果中的 name 字段手动匹配) │
```

**关键设计决策**:
- Student 与 DraftRecord 无 FK 关联 → 复核确认时按 `name` 字符串匹配
- SessionMetric 使用 `@@unique([studentId, sessionId])` (v0.4) → sessionId 可空，有课次时每课次独立，无课次时以 null 区分
- Event/Communication 通过 sessionId 绑定课次 (v0.9) → 日期从 ClassSession.date 获取
- labels 用 JSON 字符串存储

## 2. 表结构详情

### 2.1 Student

```prisma
model Student {
  id         String   @id @default(cuid())
  name       String
  class      String
  studentId  String   @unique
  gender     String                        // "男" | "女"
  labels     String   @default("[]")       // JSON array, e.g. ["#逻辑强","#敏感"]
  createdAt  DateTime @default(now())
  updatedAt  DateTime @updatedAt

  sessionMetrics SessionMetric[]
  events         Event[]
  communications Communication[]
  attendances    Attendance[]
}
```

**已知问题**:
| # | 问题 | 影响 | 建议方案 |
|---|---|---|---|
| S1 | `class` 是字符串，非独立表 | 班级重命名需逐条更新，无班级级元数据 | 抽 `Class` 表（name, grade 等） |
| S2 | `labels` 为 JSON 字符串 | 无法高效查询"所有带 #逻辑强 标签的学生"，需全表扫描后 `JSON.parse` | 建 `Label` + `StudentLabel` 关联表 |
| S3 | `gender` 为自由字符串 | 无约束，可能误填 | 加 CHECK 约束或改用枚举 |

### 2.2 SessionMetric（v0.4 重构，v0.9 改名）

```prisma
model SessionMetric {
  id        String   @id @default(cuid())
  studentId String
  date      String                        // YYYY-MM-DD
  scoreA    Int                           // 0-5
  scoreB    Int                           // 0-5
  scoreC    Int                           // 0-5
  scoreD    Int      @default(3)          // 0-5, auto-calculated
  operator  String   @default("教师")
  sessionId String?                       // v0.4：关联课次，可空
  createdAt DateTime @default(now())

  student Student       @relation(fields: [studentId], references: [id], onDelete: Cascade)
  session ClassSession? @relation(fields: [sessionId], references: [id], onDelete: Cascade)
  @@unique([studentId, sessionId])        // v0.4：每课次独立评分
}
```

**已知问题**:
| # | 问题 | 影响 | 建议方案 |
|---|---|---|---|
| M1 | 无 score 范围约束 | 数据库层可写入 0-5 之外的值 | 加 CHECK(scoreA BETWEEN 0 AND 5) |
| M2 | `date` 为 String 而非 Date | 无法利用数据库日期函数做范围查询优化 | 改为 DateTime 类型，或保持 String（SQLite 日期函数支持有限） |
| M3 | `operator` 固定为 "教师" | LLM 录入和人工录入无法区分来源 | 改为枚举或来源标识 |

**已解决**:
| # | 原问题 | 解决方式 |
|---|---|---|
| ~~M4~~ | scoreD 被 upsert 覆盖为 3 | upsert 时 create 仅设 scoreD（不设 A/B/C 默认值），update 仅改 scoreD |
| ~~M5~~ | A/B/C 按 `UNIQUE(studentId, date)` 存储，同日多课次覆盖 | v0.4：唯一约束改为 `@@unique([studentId, sessionId])`，sessionId 可空 |
| ~~M6~~ | 同日多课次考勤查询互相覆盖 | v0.3.1：考勤按 sessionCode 精确读取 |

### 2.3 Event（v0.9 重构：date → sessionId）

```prisma
model Event {
  id          String   @id @default(cuid())
  studentId   String
  sessionId   String                        // 关联课次（必填），日期从 ClassSession.date 获取
  type        String                        // "课堂表现" | "测验成绩" | "心理状态" | "家校沟通"
  description String
  rawText     String
  createdAt   DateTime @default(now())

  student Student      @relation(fields: [studentId], references: [id], onDelete: Cascade)
  session ClassSession @relation(fields: [sessionId], references: [id], onDelete: Cascade)
}
```

**已知问题**:
| # | 问题 | 影响 | 建议方案 |
|---|---|---|---|
| E1 | `type` 为自由字符串 | 无约束，可能拼写错误 | 建 `EventType` 枚举或字典表 |
| E2 | 事件无唯一性约束 | 同一事件可能重复创建 | 加 UNIQUE(studentId, sessionId, description) |
| E3 | 事件无法直接关联 SessionMetric | 无法追溯"这个事件来自哪次评分" | 加 `metricId` FK (可空) |

### 2.4 Communication（v0.9 重构：date → sessionId）

```prisma
model Communication {
  id        String   @id @default(cuid())
  studentId String
  sessionId String                        // 关联课次（必填），日期从 ClassSession.date 获取
  target    String                        // 沟通对象，如 "父亲"、"母亲"
  summary   String                        // 内容摘要
  createdAt DateTime @default(now())

  student Student      @relation(fields: [studentId], references: [id], onDelete: Cascade)
  session ClassSession @relation(fields: [sessionId], references: [id], onDelete: Cascade)
}
```

**已知问题**:
| # | 问题 | 影响 | 建议方案 |
|---|---|---|---|
| C1 | `target` 无约束 | 可能不一致（"妈" vs "母亲"） | 预设选项 + 自由输入 |
| C2 | 沟通类型缺失 | 无法区分电话/微信/面谈 | 加 `method` 字段 |
| C3 | 无唯一性约束 | 同一课次同对象可能重复 | 加 UNIQUE(studentId, sessionId, target) |

### 2.5 DraftRecord

```prisma
model DraftRecord {
  id           String   @id @default(cuid())
  rawText      String
  parsedResult String                        // JSON string
  reviewResult String?                       // JSON string
  status       String   @default("pending")  // "pending" | "confirmed" | "rejected"
  createdAt    DateTime @default(now())
}
```

**已知问题**:
| # | 问题 | 影响 | 建议方案 |
|---|---|---|---|
| D1 | parsedResult / reviewResult 存 JSON 字符串 | 不可查询、不可索引，调试不便 | 对于频繁查询的字段拆成列，其余保留 JSON |
| D2 | 与 Student 无关联 | 复核时按 name 手动匹配，姓名变更会失联 | 解析时解析出 studentId 一起存储 |
| D3 | 无 operator 字段 | 无法追溯哪个教师创建的草案 | 加 `operator` 字段 |
| D4 | 草案数据不完整 | 教师编辑后的数据覆盖了原始 LLM 输出 | 分别存 `parsedResult`(LLM原始) + `editedResult`(教师修改) |

### 2.6 Semester

```prisma
model Semester {
  id        String   @id @default(cuid())
  name      String                        // "2024-2025学年第一学期"
  startDate String                        // YYYY-MM-DD
  endDate   String                        // YYYY-MM-DD
  createdAt DateTime @default(now())

  sessions ClassSession[]
}
```

**已知问题**:
| # | 问题 | 影响 | 建议方案 |
|---|---|---|---|
| SEM2 | `startDate`/`endDate` 无校验 | 可创建 endDate < startDate 的学期 | 应用层校验或触发器 |

**已解决（v0.2）**:
| # | 原问题 | 解决方式 |
|---|---|---|
| ~~SEM1~~ | 无当前学期标识 | 当前学期按 `startDate ≤ today ≤ endDate` 判定，不再靠 `createdAt` 猜测 |

### 2.7 ClassSession（v0.2 核心改造）

```prisma
model ClassSession {
  id             String   @id @default(cuid())
  code           String   @unique         // "2026060401"，YYYYMMDDNN 全局唯一编码
  semesterId     String
  semesterNumber Int                       // 学期内序号（1, 2, 3...），增删后自动重排
  date           String                    // YYYY-MM-DD，冗余字段，从 code 推导（code.slice(0,8)）
  class          String?                   // 可空，班级名称，限定考勤范围；null 表示全校
  createdAt      DateTime @default(now())

  semester    Semester    @relation(fields: [semesterId], references: [id], onDelete: Cascade)
  attendances Attendance[]
}
```

**变更说明**:
| 变更 | 说明 |
|---|---|
| 新增 `code @unique` | YYYYMMDDNN 全局唯一编码，替代原 id 作为对外标识 |
| 新增 `class String?` | 可选班级，考勤初始化限定范围 |
| `number` → `semesterNumber` | 语义不变，按 code 排序后自动重编号（增删课次触发） |
| `date` 变为冗余 | 数据仍存，但值从 code 推导，方便索引查询 |
| 撤销 `@@unique([semesterId, date])` | 允许同天多课次，靠 code 唯一性区分 |
| API 标识改用 `code` | GET/PUT/DELETE 用 /sessions/{code} 而非 /sessions/{id} |

**已知问题**:
| # | 问题 | 影响 | 建议方案 |
|---|---|---|---|
| CS1 | `semesterNumber` 依赖应用层重排 | 并发课次增删可能序号错乱 | 加事务包装增删操作 |
| CS2 | `class` 为自由字符串 | 可能与 Student.class 不一致 | 应用层校验，或长期引入 Class 表 |

**已解决（v0.2）**:
| # | 原问题 | 解决方式 |
|---|---|---|
| ~~CS1~~ | number 非自动递增 | semesterNumber 由应用层重排，确保连续无跳号 |
| ~~CS2~~ | 删除课次后考勤未回溯 | 删除课次时同步级联删除考勤 + 重算 D

### 2.8 Attendance

```prisma
model Attendance {
  id        String   @id @default(cuid())
  sessionId String
  studentId String
  present   Boolean  @default(true)
  createdAt DateTime @default(now())

  session ClassSession @relation(fields: [sessionId], references: [id], onDelete: Cascade)
  student Student      @relation(fields: [studentId], references: [id], onDelete: Cascade)
  @@unique([sessionId, studentId])
}
```

**已知问题**:
| # | 问题 | 影响 | 建议方案 |
|---|---|---|---|
| A1 | 无缺勤原因 | 无法记录请假/旷课等区分 | 加 `reason: String?` |
| A2 | 仅布尔值无迟到 | 迟到无法记录 | 改 `present: Boolean` 为 `status: String`（出勤/迟到/请假/缺勤） |

## 3. 性能风险点

| 风险 | 位置 | 说明 |
|---|---|---|
| N+1 查询 | `/api/alerts` | 逐学生查询最近 3 条 metric，学生多时性能下降 |
| 全表扫描 | 学生详情页 | Event/Communication 未分页，历史数据积累后一次加载过多 |
| scoreD 重算 | 上课/考勤更新 | 逐学生逐条 `count` + `upsert`，O(n) 次查询 |
| labels 查询 | 所有展示 labels 的地方 | 每次 `JSON.parse()`，无法利用索引 |

## 4. 优化路线图

### 已完成 ✅

1. ✅ ClassSession 编码体系：`code` (YYYYMMDDNN) + `class` + `semesterNumber` 自动重排 (v0.2)
2. ✅ 撤销 `@@unique([semesterId, date])`，允许同天多课次 (v0.2)
3. ✅ scoreD 覆盖保护 (v0.2)
4. ✅ 当前学期按日期判定 (v0.2)
5. ✅ 删除课次自动重算 D + 学期内序号重排 (v0.2)
6. ✅ **课次级评分**: DailyMetric unique 改为 `(studentId, sessionId)`，同日多课次独立评分 (v0.4)

### 短期（不改 Schema，加约束和修复）

1. Event: 加 `metricId` FK (可空) 建立评分-事件关联
2. DraftRecord: 解析时查出 studentId 一并存储
3. 加应用层数据校验（score 范围、日期逻辑等）

### 中期（Schema 微调）

4. Student.labels → 独立的 `Label` + `StudentLabel` 关联表
5. Attendance.present → status 枚举（出勤/迟到/请假/缺勤）
6. Communication: 加 `method` 字段

### 长期（大型重构）

7. `class` → 独立 `Class` 表
8. DailyMetric 的 A/B/C/D 维度 → 支持自定义维度的 EAV 模型
9. DraftRecord 的 JSON 字段拆成结构化列
10. 引入分页和游标查询
