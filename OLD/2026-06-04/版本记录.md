## v0.9.0 — 数据模型课次化重构 (2026-06-04)

### 核心变更：Date 解耦 + 模型改名

**核心理念**：从"自然日期"为中心改为"课次"为中心。Event 和 Communication 不再绑定 `date` 字符串，全面绑定 `sessionId`。

### Schema 变更

- [x] **DailyMetric → SessionMetric**: 模型重命名，数据库表名同步变更
- [x] **DailyMetricHistory → SessionMetricHistory**: 归档表同步重命名
- [x] **Event**: 删除 `date` 字段，新增 `sessionId String`（必填）+ `session ClassSession` 关联，`onDelete: Cascade`
- [x] **Communication**: 删除 `date` 字段，新增 `sessionId String`（必填）+ `session ClassSession` 关联，`onDelete: Cascade`
- [x] **Student**: `metrics` → `sessionMetrics` 反向关系改名
- [x] **ClassSession**: 新增 `events Event[]`、`communications Communication[]` 反向关系，`metrics` → `sessionMetrics`

### 行为变更

- [x] Event/Communication 创建必须有 `sessionId`（无课次场景下跳过创建）
- [x] 日期信息通过 `session.date` 间接获取
- [x] 查询 Event/Communication 按日期范围改为 `where: { session: { date: {...} } }`
- [x] 导出 Excel 中 Event/Communication 增加"课次编码"列

### Bug 修复

- [x] **批量反馈导出 0 字节文件** (2026-06-04): 两个根因 — ① `Content-Disposition` 头中 `反馈` 中文文件名导致 Node.js HTTP 层 ByteString 校验失败 → NextResponse 构造抛异常 → 500 空响应；② POST 循环中的进度缓存（空 buffer）可能因请求中断残留，下次命中直接返回空缓存。修复：文件名改为 ASCII `feedback_`；移除无效的进度缓存条目。
- [x] **SSE 流式解析丢失末尾事件** (2026-06-04): TextDecoder `{ stream: true }` 模式下未调用最终 `decode()` flush，导致末尾 UTF-8 多字节残留 → `\n\n` 定界符被破坏 → 最后几个学生反馈丢失（"不生成"）。同时循环结束后未处理 residual buffer。修复：`done` 时传 `{ stream: false }` + 显式 `decoder.decode()` flush + `indexOf("\n\n")` 逐条解析 + `finally releaseLock`。

## v0.4.0 — 课次级评分 Schema 重构 (2026-06-04)

### 核心变更：A/B/C 分数改为每课次独立存储

**问题**：`DailyMetric` 唯一约束为 `@@unique([studentId, date])`，同日多课次 A/B/C 共享/覆盖同一条记录。

### Schema 变更

- [x] **DailyMetric**: 新增 `sessionId String?` — 关联 `ClassSession`（可空，NL 输入等无课次场景为 null）
- [x] **DailyMetric**: 唯一约束改为 `@@unique([studentId, sessionId])` — 每课次/每次评分独立一行
- [x] **DailyMetric**: 新增 `session ClassSession?` 反向关系，`onDelete: Cascade`
- [x] **ClassSession**: 新增 `metrics DailyMetric[]` 反向关系

### API 变更

- [x] **GET /api/quick-score**: 有 `sessionCode` 时按 `sessionId` 精确查询；无 sessionCode 时查 `sessionId=null` 的旧记录
- [x] **POST /api/quick-score**: 解析 `sessionCode` → `sessionId`，upsert key 改为 `studentId_sessionId`
- [x] **POST /api/review** (NL 复核): upsert → findFirst + update/create（sessionId=null）
- [x] **PUT /api/attendance**: scoreD 改为更新学生最新 metric（不创建 A/B/C=0 的新行）
- [x] **recalculateScoreD**: 同上
- [x] **GET /api/alerts**: 最新 metric 排序改为 `createdAt: desc`；班级概览改为每学生只取最新一条（避免重复计数）

### 附加修复 (同版本)

- [x] **scoreD 污染预警**: 不再创建 A/B/C=0 的 scoreD 行，改为更新已有 metric 的 scoreD
- [x] **班级概览重复计数**: 改为每学生取最新 metric 参与平均，不再统计所有历史行
- [x] **学生详情排序**: `orderBy` 增加 `createdAt: desc`，同日多条 metric 按时间正确排序

### 已解决问题

- [x] ~~**M5**~~ **同日多课次 A/B/C 评分覆盖**: `DailyMetric` 唯一约束改为 `@@unique([studentId, sessionId])`，每课次独立一行
- [x] ~~**L1**~~ (v0.3.0 已知限制) **同日多课次 A/B/C 共享**: 同上

## v0.3.1 — 课次切换考勤刷新修复 (2026-06-04)

### Bug 修复

- [x] **课次切换后卡片不刷新**: 根因不是 React 渲染层，而是 `GET /api/quick-score` 只按 `class + date` 查询，并把同一天所有课次的考勤按 `studentId` 合并，导致同日同班多课次互相覆盖。
- [x] **GET /api/quick-score**: 新增 `sessionCode` 查询参数；传入课次编码时，考勤只读取该 `ClassSession.id` 下的记录。
- [x] **快速评分页**: `loadSessionCards` 改为传 `sessionCode`，切换课次后卡片考勤会按当前课次刷新。
- [x] **日期查询保护**: 未传 `sessionCode` 时，只有同班同日唯一课次才回填考勤，避免不明确的同日多课次数据污染。

### 仍需注意

- [ ] **同日多课次 A/B/C 分数仍按日期共享**: `DailyMetric` 目前是 `UNIQUE(studentId, date)`，同一天多次评分会覆盖同一条 A/B/C。若要做到同一天每节课独立评分，需要后续 Schema 增加课次级评分关联。
