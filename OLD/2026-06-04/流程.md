# 开发流程规范

> **目标**: 确保每次 AI 会话的工作可追溯、可延续，减少上下文丢失和重复劳动。  
> **核心原则**: 文档驱动开发，改代码必改文档。

---

## 1. 文件分类

### 🟢 持续维护的文件（每次改动后必须同步更新）

这些文件是项目的"记忆"，如果改了代码但没更新这些，下次新会话就会遗漏信息。

| 文件 | 何时更新 | 更新内容 |
|---|---|---|
| `文档/需求目录.md` | 完成/新增功能时 | 改对应条目的状态标记 + 备注 |
| `文档/版本记录.md` | 每次发布/修 Bug/合并 PR | 新版本号 + 变更项 + Bug 修复记录 |
| `文档/数据结构文档.md` | 修改 Schema 时 | 更新表结构 + 新增/解决已知问题 |
| `文档/需求文档.md` | 功能行为发生实质变化时 | 更新对应功能模块的描述 |
| `文档/AI对接文档.md` | 技术栈变更、新增重要文件、编码规范变化时 | 更新对应章节 |

### 🟡 按需更新的文件

| 文件 | 何时更新 |
|---|---|
| `文档/流程.md`（本文件） | 流程本身需要调整时 |
| `档案中心规划文档.md` | 仅作历史参考，一般不改 |

### 🔴 不应手动编辑的文件

| 文件/目录 | 原因 |
|---|---|
| `src/generated/prisma/` | Prisma 自动生成，schema 变更后 `prisma generate` 自动更新 |
| `.next/` | Next.js 构建输出，`npm run dev/build` 自动更新 |
| `node_modules/` | npm 管理 |
| `package-lock.json` | npm 管理（除非刻意新增/升级依赖） |
| `dev.db` | SQLite 数据库文件，通过 Prisma 操作，勿直接编辑 |
| `tsconfig.tsbuildinfo` | TypeScript 增量编译缓存 |

## 2. 单次开发任务的标准流程

### 2.1 任务开始前

```
[ ] 1. 阅读 文档/需求目录.md — 确认要做的功能当前状态
[ ] 2. 阅读 文档/数据结构文档.md — 确认是否有已知问题会影响本次任务
[ ] 3. 如果涉及 Schema 变更，先查阅数据结构文档的优化路线图
[ ] 4. 启动 dev server，验证当前系统正常运行
```

### 2.2 编码过程中

```
[ ] 1. 只改与任务直接相关的文件（Karpathy 原则：外科手术式修改）
[ ] 2. 不在本次改动中顺手"优化"无关代码
[ ] 3. 涉及数据模型变更时：
     a. 先改 prisma/schema.prisma
     b. 运行 npx prisma migrate dev --name "描述"
     c. 更新 文档/数据结构文档.md
     d. 按需更新 seed.ts
[ ] 4. 涉及 API 变更时，确保前后端类型一致
[ ] 5. 涉及 LLM Prompt 变更时，记录改动原因到版本记录
```

### 2.3 任务完成后

```
[ ] 1. 验证功能可跑通（浏览器手动测试 + 控制台无报错）
[ ] 2. 更新 文档/需求目录.md — 标记完成状态
[ ] 3. 更新 文档/版本记录.md — 记录变更内容
[ ] 4. 如果改了数据模型 → 更新 文档/数据结构文档.md
[ ] 5. 如果改了功能行为 → 更新 文档/需求文档.md 对应章节
[ ] 6. 如果改了技术栈/项目结构/编码规范 → 更新 文档/AI对接文档.md
[ ] 7. 用 git 提交，commit message 遵循格式: "[类型] 简短描述"
     类型: feat / fix / refactor / doc / chore
```

## 3. Commit Message 规范

```
格式: [类型] 功能模块: 简短描述

示例:
  [feat] quick-score: 新增评分历史覆盖提示
  [fix] parser: LLM JSON 解析增加空串检查和 token 截断检测
  [refactor] attendance: D 分数重算逻辑抽为独立工具函数
  [doc] 新增开发流程规范文档
  [chore] 升级 prisma 到 7.9.0
```

## 4. 文档维护职责矩阵

| 变更类型 | 需求目录 | 版本记录 | 数据结构文档 | 需求文档 | AI对接文档 |
|---|---|---|---|---|---|
| 新增功能 | ✅ 标记完成 | ✅ 记录 | — | 🟡 如行为有变 | — |
| 修复 Bug | 🟡 如影响了功能状态 | ✅ 记录 | — | — | — |
| 改 Schema | — | ✅ 记录 | ✅ 更新表+问题 | 🟡 影响 API 行为 | — |
| 改 LLM Prompt | — | ✅ 记录原因 | — | ✅ 更新 Prompt | — |
| 改编码规范 | — | — | — | — | ✅ 更新 |
| 新增依赖 | — | ✅ 记录 | — | — | 🟡 如影响启动流程 |
| 重构（无行为变化） | — | ✅ 记录 | — | — | — |

## 5. 新 AI 会话启动模板

每次新会话开始时，AI 应走这个流程：

```
第 1 步: 读 文档/需求目录.md → 了解当前功能完成情况
第 2 步: 读 文档/流程.md → 确认本次的开发规范
第 3 步: 根据用户任务，选择性读：
        - 改哪块功能 → 读 文档/需求文档.md 对应章节
        - 改数据库 → 读 文档/数据结构文档.md
        - 不确定怎么跑 → 读 文档/AI对接文档.md
第 4 步: 检查项目能正常启动 (npm run dev)
第 5 步: 开始工作
第 6 步: 工作完成后按 2.3 节更新文档
```

```
│   └── src/                   # 源代码

```

> ⭐ = 每次会话必读 / 每次改动必更新
