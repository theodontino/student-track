# 设计决策

本文件只记录影响长期维护、且无法仅从代码中看出原因的选择。

## 1.0 前只做维护与稳定性修复

Student Track 进入 1.0 收敛期，不再直接加入新产品能力。维护、稳定性、兼容性、隐私和缺陷修复可以继续进入主线；任何需要明显改变工作流、领域规则或产品边界的提议必须先建立 GitHub Issue，确认当前方案走不通后才单独设计和实施。

## 自动化通过后直接进入真实使用

Student Track 是单教师、本地优先且持续使用的工作台。日常改动以自动化验证为发布门禁：普通改动通过 `verify:quick`，Schema、数据写入、高风险改动和稳定版通过 `verify:release` 后即可投入真实使用；真实使用负责持续发现产品问题，不要求发布前固定重复若干次人工流程。

所有 `verify:*` 命令必须在运行前后自动确认真实 SQLite 主文件和 WAL 的 size、mtime、SHA-256 完全一致，证明测试隔离没有失效。人工冒烟只在无法由仓库自动化充分覆盖且相关边界确实变化时触发，例如 WCG Accessibility/草稿填入、破坏性 migration、安装签名和进程托管；同一提交已通过的本地或 CI 全量验证不重复运行。

## 产品名称统一为 Student Track

产品、界面、文档和发布名称统一使用 `Student Track`；npm 包、本地项目目录和 GitHub 仓库使用 `student-track`。文档不维护已废弃名称、路径或数据格式的操作说明。

## SQLite 与 Prisma

当前使用 SQLite 和 Prisma。产品处于单人、本地优先验证阶段，SQLite 已满足数据量与并发需求；Prisma 提供迁移、类型和统一数据访问。只有出现明确的多用户并发、远程部署或 SQLite 限制时，才评估 PostgreSQL。

## 只支持本机访问

Web 服务显式绑定 `127.0.0.1`。当前产品不面向局域网或公网用户，因此不引入认证和远程部署基础设施。如果未来要求远程访问，必须先单独设计身份认证、授权、网络边界和敏感操作保护。

## WCG 与 WCL 保持边界

WCG（WeComCatch GUI）是当前唯一开发的企微归档配套应用；WCL（WeComCatch Legacy）只作为历史版本保留其 OpenClaw 相关能力。Student Track 不包含或分发两者的源码、运行数据及本地配置，也不读取或启动其进程。唯一在线耦合是 WCG 的认证、只读、可缓存花名册 API；业务数据只通过固定的 handoff v1 文件协议交付。公开 Student Track 不代表公开、授权或推荐该外部工具；
使用者应自行确认平台协议、组织授权和个人信息处理依据。

交换目录和只读目录 API 状态检查与第三方工具须知留在系统中心；“企微家校”工作区
只提供中转仓库和教师复核。主导航入口仍需在当前浏览器确认须知后显示。

## 领域模型优先于通用模型

系统以 `Student`、`Class`、`Semester`、`ClassSession`、`SessionMetric` 和 `Attendance` 为核心，不提前建立通用“内容”“任务”“考试”“分数”抽象。新表必须对应具有独立生命周期的业务概念。

## 渐进式 Service 层

不一次性为所有表建立 Repository 和 Service。简单 CRUD 保持在 Route Handler；出现多表事务、复杂规则或多入口复用时再抽离 Service。这样既形成清晰边界，也避免样板代码成为主要维护成本。

## 原生客户端采用渐进式迁移

Student Track 采用“稳定 Web 基线、独立原生客户端、版本化本地 API”的渐进路线，不进行一次性 SwiftUI 重写。现有 Web 继续作为完整能力的兼容入口；未来 macOS 原生客户端放在独立项目中，通过只绑定回环地址的版本化 API 复用 Student Track 后端与 Service，不直接访问 Prisma、SQLite、LLM 配置或服务端运行目录，也不在客户端复制评分、考勤、反馈、批准和导出规则。

主仓库不预先复制全部现有 Route。只有第二客户端实际需要的工作流才建立稳定的跨客户端契约，版本化适配器与 Web Route 复用同一 Service。尚未迁移的能力继续使用 Web；已经迁移的能力保持相同的领域语义、教师确认点、数据生命周期和安全门禁，原生界面不必复制 Web 的视觉实现。

跨客户端契约发布后不得在原版本中原地改变字段语义。破坏性变化必须先更新契约与兼容测试，并提供新版本或明确的迁移、弃用窗口。原生客户端所需的认证、后端进程生命周期、可分发打包、签名与公证属于原生阶段的前置设计；在完成设计和验证前，不将其写成当前已支持能力。

## 规则使用代码配置

可变化的预警阈值、评分常量和计算参数先放在 `src/config/` 的类型化配置中，不引入数据库配置中心或管理后台。只有实际出现教师自行配置需求后，才增加持久化设置。

## LLM 结果必须复核

自然语言解析和反馈生成允许使用 LLM，但学生身份、班级范围、考勤补齐和数据库写入由确定性代码控制。NL 解析结果先进入草案，经教师复核后才能成为正式业务数据。

课后反馈采用受控的两阶段模型流程：分析模型先依据确定性上下文整理本次表现、近期趋势和历史联系，成稿模型再独立对照同一份上下文复核并写成家长话术，只能通过、修订或标记为需要人工确认，不得补写上下文中没有的事实。内部分析保存在本机缓存和 `GenerationRecord` 审计中但不导出；成稿输出无法解析、为空或疑似混入其他学生时，不得回退使用内部分析，并阻止导出，直到教师修改或重新生成。成稿模型无法发现源记录本身错误，因此生成前上下文预览和最终人工检查仍然保留。

WCG handoff 的模型结果只作为候选事实。Student Track 必须重新验证短消息引用、学生匹配和课次边界；任何不确定项进入教师复核。只有教师确认 `DraftRecord` 后才写入正式沟通，模型不得直接创建课次、行动建议或学生关注标签。

## handoff 消费保持幂等与可审计

Student Track 只接收已完成 marker 的不可变 handoff 包，并以包身份与 SHA-256 保证幂等。路径、大小、Schema、哈希、学生唯一匹配和证据校验任一失败时，包不产生正式沟通；处理结果由不可变回执写回交换目录。学期日期范围可以重叠，handoff 匹配以覆盖全部证据日期的候选学期名单并集为范围，再以学生在候选范围内唯一的学期归属消歧；不得因为日期命中多个学期就直接要求人工匹配。教师确认的学生映射按 `sourceId + conversationId` 复用，但每个新包仍重新校验当期归属，映射冲突时回到人工处理。

历史账本默认只用于审计和受控的 `receiptId` 修复；为兼容新增的会话身份字段，重复扫描可只补齐旧账本缺失的 `conversationId`，不改写包状态、草案或正式沟通。既有 `pending_alignment` 的自动恢复必须先执行只读预检，教师输入明确确认短语后才可顺序处理，单次最多 25 包；预检仍无法唯一匹配的包保持不变。

## LLM 原始交互使用本机操作缓存

模型输入、原始输出和推理内容可能是排障所必需，但不适合进入长期 Prisma 账本。它们按任务类型和一次用户操作保存在 Git 忽略的 `data/llm-cache/`，权限限制为当前用户；数据库只保存模型名、提示词版本、结束原因、token 数量、响应字符数和错误分类等非敏感诊断。某类任务下一次完整成功后清除该类更早缓存，失败只保留当天；跨日和总容量规则进一步限制留存。

## 历史账本与回执修复

历史账本保留为只读数据，不删除表、不改写历史行，也不参与当前工作流。handoff 的回执修复是唯一允许的维护写入：必须先只读校验包、marker、SHA-256、台账身份和终态；实际执行前创建并验证数据库备份，并且只补原台账行的 `receiptId`，不改变包、状态、草案或正式沟通记录。

## 录入与反馈共用课后工作台

自然语言录入、草案复核、反馈生成和导出属于同一次课后任务，因此在一个可恢复的五步工作台中组合。准备阶段只维护学期级或课程级公共材料；课堂文字、助教 Excel 和出门测 PDF 在录入阶段形成当前课次输入；反馈计划在复核阶段创建并在生成、导出阶段继续使用。

## 1.2 Beta 3 统一材料入口保持双轨

Beta 3 将默认 `/feedback` 改为教师主动打开后的一次性三段式课后任务：固定收件箱、拖拽/选择文件和 ZIP 先合并到同一轮材料，再在“确认事实”阶段处理异常，最后进入既有 FeedbackPlan 工作室。读取不会常驻监听，也不会移动或删除源文件；扫描阶段不写课堂事实，教师确认后才由一个事务应用无冲突事实和已选决策。STEP 仍是 `experimental`，只按稳定 `studentId`、姓名、班级和课次边界写入明确考勤、课堂观察和教师动作，不补评分、不推断缺勤、不持久化坐标，模型候选与异常必须由教师处理。PDF 只进入本次 FeedbackPlan 证据快照。

## 1.2 Beta 4 由主班推进班级组共同进度

班级组不是课次容器，而是共享教学进度的平行班集合。每组显式指定一个主班，由主班真实课次创建或推进第 N 讲共同课；其他班默认补齐主班已经开始的最早一讲。主班未推进时不允许从班代替主班创建共同课，从班课次正常建立但保持独立。教师日常无需理解 `GroupLessonSession` 或逐次确认挂靠，只有补课、停课和临时不同进度才在学期详情调整。共同材料仍先保存草稿，确认修订后才供其他班复用。

统一入口创建的仍是既有 `FeedbackPlan`。标准/快速生成、逐学生编辑、批准、历史、批次和 WCG no-send 边界不复制一套新规则；完整五步工作台保留在 `/feedback/advanced`，旧按钮、Route Handler 和带 `planId` 的深链接继续可用。确认共同课修订时按真实课次关联自动带入，创建计划时复制快照，之后不实时引用共同课草稿。

## FeedbackPlan 是反馈流程和反馈历史的唯一权威

自 1.1.1 起，教师日常反馈流程和历史恢复只读取 `FeedbackPlan`。计划保存版本化
`inputSnapshot`、课次范围、学生条目、证据、教师最终文本和生成状态；`GenerationRecord`
只作为模型审计账本，不作为教师历史入口。`sessionStorage` 只保留当前标签页的未提交课堂文字、
结构化草案和解析后的 PDF 摘要，不承担长期历史。

已生成、批准、导出或带附件的计划只能归档；只有没有生成记录、批准、导出、正文和附件的纯草稿
允许删除。旧 `WorkHistory` 数据不转换为反馈计划，升级前通过备份和只读合成库验证后删除旧表。
旧草案中心和 AI 审计入口保留为路由兼容重定向，不能继续向旧系统写入。

## 反馈计划采用三层流水线与可选模块

反馈计划在独立 `FeedbackPlan` 账本中保存四类反馈类型和不可变的批准/导出版本，避免把旧批量反馈状态误当成新计划批准记录。服务先用确定性代码构建证据包，再按计划快照允许模型自然组织模块和初稿；空模块范围表示使用当前类型的完整目录，非空范围只允许使用已选模块。审核模型只能对同一证据包做受限复核与润色，最后由程序硬门禁和教师批准放行。个人反馈不强制家庭动作；教师处理、家庭动作和后续观察分别受证据、开关和 `TeacherTask` 约束。结课反馈只做教学总结，不做续班或服务适配判断。该边界在首版保留，WCG 发送和正式测评体系另行设计。

已批准的个人反馈可以导出为独立的 `student-track.wecom-draft-package.v1` JSON，供 WCG
在本机校验学生映射后逐条调用既有 `draft-fill-v1`。该包不是发送命令或发送回执，
不改变 WCG → Student Track 的 handoff v1；Student Track 不直接控制企微，也不得把
草稿呈递或填入状态记录为消息已发送。

## 音频转写优先纯文本

Student Track 的课堂录音转写优先生成可复核的纯文本，而不是追求说话人分离、时间轴或会议纪要结构。当前业务目标是把课后评价内容更快送入 NL 录入；说话人标签和时间轴会增加阅读噪音，也会提高本地模型配置和故障排查成本。

本地转写使用 FunASR/SeACo 与热词增强。热词来自基础化学词表和当前学生姓名，属于输入质量增强，不改变学生身份匹配和业务写入规则。只有出现明确的课堂互动分析需求时，才重新评估说话人分离和时间轴。

## 历史分层保存

评价历史、反馈计划历史、模型审计、系统日志和数据库备份解决不同问题，因此分别保存。反馈历史
按学期、班级、课次、学生、课程日期、状态和归档状态筛选；阶段计划的日期按截止课次计算。数据库
恢复只能使用通过完整性与校验和检查的备份。

## 班级和学生归属按学期隔离

每个学期创建独立的 `Class` 实体和班级 ID；班级编号只在同一学期内唯一，因此不同学期可以复用编号。`Student` 只保存跨学期稳定的个人档案，`StudentClassEnrollment` 保存某学生在某学期的唯一班级归属、花名册状态和生效时间。

选择学期是班级名单、导入、建课、反馈和 WCG 目录的必需上下文。转班更新当期归属并写系统日志，历史课次、评价、考勤、事件、沟通和反馈账本保持原样；已停用学生仍可查看和修订已有历史课次。暂不建立跨学期 `ClassSeries` 或同学期多课程归属，未来需求另建 Issue。

## 文档只保留稳定认知

长期文档不记录待办、文件数量或测试数量。当前稳定版本和跨仓库兼容性集中记录在 `RELEASES.md`；机械事实由脚本生成，功能提议、缺陷、重构和重大产品变化使用 GitHub Issues，减少每次改代码时同步多份文档的负担。

## SheetJS 使用官方发布源

Excel 导入导出继续使用 SheetJS Community Edition，但依赖指向 SheetJS 官方 CDN 的固定版本 tarball。npm registry 中的 `xlsx` 长期停留在旧版本并包含已知安全告警；固定官方 tarball既保留现有 Excel API 和格式兼容，也避免为了消除告警更换整套导入导出实现。升级前必须运行花名册导入、反馈导出和五 Sheet 数据导出回归测试。

## 使用 AGPL-3.0-only

Student Track 以 `AGPL-3.0-only` 发布。允许个人和组织使用、修改、分发及商业运营，但修改版被分发或用于向用户提供网络服务时，必须向相应用户提供完整对应源代码并继续使用同一许可证。选择 `only` 而不是 `or-later`，避免未来 GNU 许可证版本自动改变授权范围。

许可证只覆盖仓库中的软件和文档，不授权公开学生数据、运行数据库、音频、导出、日志或用户生成内容。theodontino 保留版权，并可在拥有完整版权的范围内另行提供商业许可证。

## 浏览器本地配色而非业务配置

界面提供经典、暮蓝、星云和平衡星云四套配色，默认使用平衡星云。配色只改变语义 token，并保存在当前浏览器 `localStorage`；不增加数据库字段、服务端设置或用户体系。页面首次绘制前由根布局应用已保存配色，避免深浅主题闪烁。

动效使用 CSS 和浏览器原生能力，不增加动画状态库。内容区使用较厚、较不透明的磨砂材质，液态玻璃感只用于导航和浮层；主题与动效都必须尊重可访问性、对比度和 `prefers-reduced-motion`。
