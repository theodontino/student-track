# 提示词维护准则

Student Track 的提示词是教师工作流的一部分，不是可以随意重写的实现细节。已经由教师亲手调整并在真实反馈中验证过的表达、顺序和留白，应视为有意设计。除非教师明确要求整体重写，否则维护时不得大规模搬动、重新编号、统一措辞或按开发者偏好整理现有提示词。

## 硬边界与软引导

硬边界只用于程序必须保证的事实：学生与课次身份、证据来源、隐私、跨学生内容、收件人、结构化协议、业务写入和不能凭空承诺的动作。能由确定性代码校验的边界优先放在代码中，不依赖反复提醒模型。

表达详略、语气、句式、信息密度、教师判断的展开方式和自然程度属于软引导。软引导说明目标和可用空间，不穷举禁用句、不规定固定段落顺序，也不转化成阻断保存或导出的程序门禁。不要为了修复一次不理想输出，不断追加同义限制，让模型只能复述提示词。

## 反馈生成原则

- 草稿以召回和展开为主。证据、可能的联系和有依据的教师判断应充分进入草稿，删减与最终取舍留给审核模型和教师。
- 审核优先修正事实、身份、收件人、隐私和越界承诺；对有依据但表达不够成熟的判断，优先降低确定性、补充自然过渡或提示教师确认，不主动压缩成统一模板。
- 所有已确认教学与测评证据都应参与草稿推理和覆盖审计，但家长文本不必逐项暴露原始数据。优先保留总正确率和有明确可比基础的变化等标志性数据，其余证据可被消化为知识、方法和能力判断。
- 长期判断必须来自跨时间、可比较且指向同一能力的重复证据。单次表现只能解释本次，不得外推为人格或长期能力。
- 默认收件人是家长。模型不得自行根据聊天内容切换为对孩子讲话；特殊收件人必须由教师明确决定。
- 家长文本不采用固定的“表现—数据—建议”顺序。模型可以从教师判断、课堂瞬间、变化或家长最关心的问题自然展开。
- 教师手工修改的最终文本具有最高编辑权。重新生成、审核、兼容处理和迁移不得静默覆盖教师文本。

整体取向是“多写、慢改、少删”：删减容易，重建被过早压掉的证据联系和教师判断更困难。模型应有形成判断和自然表达的空间，教师负责最终取舍。

## 修改与验证

修改现有提示词时保持局部、可解释和可回退。不要顺手重排无关段落；需要整体改写时，先保留当前版本并明确说明影响范围。提示词版本变化只影响之后的新生成，既有草稿和教师成稿不得自动重写。

自动化测试只验证技术契约，例如输出结构、证据引用、身份隔离、收件人门禁、失败回退和教师文本不被覆盖。测试不锁定完整提示词字面量，也不把某种审美、语序或价值判断固化为字符串断言。
