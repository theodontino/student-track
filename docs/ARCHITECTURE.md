# 架构设计

## 目标

Student Track 是单人维护的本地优先课后反馈自动化工具。架构优先保证数据安全、业务规则可读和低维护成本，不为尚未出现的并发或组织规模预建基础设施。Web 服务只绑定 `127.0.0.1`；当前不支持局域网或公网部署，也不以缺少身份认证的状态对外暴露。

## 前端模块边界

App Router 页面只组合 Feature 工作台或执行兼容重定向。交互状态、请求和历史恢复归属 `src/features/`；通用控件归属 `src/components/ui/`，HTTP JSON 与文件下载归属 `src/lib/api-client.ts`。Feature 通过公开入口复用共享能力，不直接引用另一个 Feature 的内部文件。

学期、班级、课次采用显式 URL 上下文：`semesterId`、`classId`（同时保留可读的 `class`）、`sessionCode`。学期变化清空班级和课次，班级变化清空课次。班级选项必须从所选学期的 `/api/semesters/:id/classes` 读取，不能从全局学生列表猜测。URL 是当前页面的事实来源；标签页级 `sessionStorage` 只记录最近教学上下文，用于在工作台之间导航时补全 URL，不作为全局数据缓存。

未提交的页面工作状态使用带版本包装的标签页级 `sessionStorage` 保留，涉及教学数据的工作台按“页面 + 学期 + 班级 + 课次”隔离，避免把旧草稿恢复到另一课次。工作台只能通过 `src/lib/session-workspace.ts` 和对应 hook 读写，必须校验恢复数据，版本不匹配时放弃恢复。该存储用于切换页面和刷新后继续当前工作，不替代数据库 `WorkHistory`。凭据、API Key、未提交的 `File`/`Blob` 和录音流不得写入页面工作状态；浏览器无法安全恢复的本地文件必须在离页前提醒。已创建的转写任务只保留任务 ID，结果仍从服务端任务目录读取。

展示型 TSX 由 Playwright 覆盖关键工作流和窄屏导航；Vitest 的显式统计范围为 `src/app/api/**/*.ts`、`src/services/**/*.ts`、`src/lib/**/*.ts` 和 `src/features/**/*.ts`，并排除展示型 TSX、纯类型与入口文件。这样新增但尚未被测试加载的逻辑也会进入统计，页面从 `app/` 迁入 Feature 时不会改变覆盖率口径。逐版本覆盖率属于构建结果，保留在对应发布记录或 CI 报告中，不写入稳定架构文档。

AI 任务通过 `src/features/ai-workflow/` 的判别联合与 reducer 表达校验、生成、复核、保存、完成、失败和取消。页面刷新后，仍处于运行阶段的存档必须恢复为可重试的中断状态，不能假装后台任务仍在继续。该状态只记录任务名称、阶段、时间和安全提示，不保存凭据、文件或模型请求正文。

批量反馈页面状态还必须保存服务端计算的输入指纹、当前阶段、学生总数、已处理与失败学生 ID 及中断原因。取消、断网或刷新后，已收到卡片继续可见，但批次恢复为 `incomplete` 并禁止导出；继续处理前由服务端按当前课程材料、PDF 证据、反馈档位和输出策略重算指纹，只对未完成或失败学生调用单人生成。教师可显式把部分结果保存为不可导出的 `WorkHistory`，或放弃整个旧批次。输入指纹或学生总数变化时状态转为 `stale`，旧卡片只能核对，不能与新结果合并。内存缓存和导出 Service 都不得把 `incomplete` 状态当成完整批次。

快速评分的参考资料、课次协调和保存/历史职责分别由独立 hook 管理；页面组合 hook 不重复实现差异提交或 ref 协调。录音转写同样把浏览器录音、任务 API、任务列表和结果操作分离，服务端任务 ID 是跨页面恢复的唯一运行标识。

仪表盘的数字风险必须按单一学期、实际课次班级和同课次班均计算；未来课次、无课次评价和其他学期数据不得混入。前四次课的相对表现、第五次课后的近期评分回落与长期低于班均均由纯规则模块计算。近期评分回落比较最后 20% 有效课次与学生本学期个人总体平均，至少需要 5 次有效评价。已触发考勤提醒的学生不再进入上方学习风险候选和早期排名。全局内部关注标签只在当前自动解析学期作为一个定性条件参与叠加，不能改写历史学期结果。Dashboard 加载不得调用 LLM。

课堂录入仍可使用受控的内部关注原因枚举；WCC handoff 消费不生成或写入学生关注标签。所有家长反馈上下文必须先过滤 `AI内部关注：*`，不能依赖提示词要求模型自行忽略。

学生档案的学期四维平均和综合分由 Service 按请求批量聚合，列表和详情复用同一计算规则。该结果是可重建的展示数据，不写入数据库或浏览器缓存；修改评价、考勤或课次后，下次请求必须从原始记录得到最新结果。列表聚合禁止逐学生查询，只有真实规模验证超过既定性能阈值时才另行论证持久化缓存。

`StudentClassEnrollment` 是花名册和班级业务的唯一入口。学生列表、WCG 目录、批量反馈和自动流程必须显式带 `semesterId`，并由共享 Enrollment Service 过滤 `ACTIVE`；API 可以为兼容客户端投影返回 `classId`、`classCode`、`class` 和状态，但这些字段不再来自 `Student`。状态转换写安全系统日志，重复请求幂等；转班只更新当期归属，不删除、不回写且不重新解释任何历史业务数据。

当前学期优先选择日期范围覆盖今天且 `startDate` 最新的学期；无匹配时回退到拥有最近课次的学期，再回退到开始日期最新的学期。学生是否参与某学期由 `StudentClassEnrollment` 明确记录；升级旧数据时才从课次证据推导历史归属，历史班级归属以日期最新的课次为当前推导结果。

## 请求链路

```text
Page / Component
  -> Route Handler
    -> Service（复杂业务、事务、跨入口复用）
      -> Prisma
        -> SQLite
```

- 页面负责交互和展示，不直接访问 Prisma，不承载业务判断。
- Route Handler 负责输入解析、HTTP 状态和响应格式。
- 简单单表 CRUD 可以直接使用 Prisma。
- 多表写入、复杂规则、事务或多入口复用进入 `src/services/`。
- Repository 只在复杂查询被多个 Service 重复使用时建立，不作为固定层级。
- 教师或机构可能调整的规则进入 `src/config/`；数据库约束与稳定领域不变量保留在 Schema 或 Service。

所有外部输入在 Route Handler 边界使用 `src/lib/contracts/` 的 Zod schema 校验。课堂解析、课后反馈和转写的流式事件统一通过 `src/lib/sse.ts` 解码；格式错误、截断和取消不会被当作正常完成。批量反馈缓存使用带 TTL 和容量上限的内存 LRU，不设置永久定时器，也不保存学生正文到浏览器缓存。

`src/proxy.ts` 只允许回环地址上的精确同源 API 请求；浏览器提供 `Origin` 时必须与请求 URL 的协议、主机和端口完全一致，不能把 `localhost`、`127.0.0.1` 和 `::1` 相互替代，也不接受 `Sec-Fetch-Site: same-site`。跨源、跨站或外部 Host 直接返回受控 `403`。缺少浏览器 Fetch 元数据的本机 CLI/测试请求仍可通过，但不放宽回环地址限制。生产服务仍只绑定 `127.0.0.1`，这层检查不能替代未来真正的身份认证。

## 数据边界

`prisma/schema.prisma` 是数据库结构的唯一事实来源。Schema 变更必须通过 migration，并在全新数据库和现有数据升级路径上验证。

一次用户动作涉及多个核心写入时必须使用事务。例如确认录入草案时，评价、考勤、事件、沟通和草案状态要么共同成功，要么共同失败。操作日志和页面工作历史属于辅助数据，可以在核心事务成功后独立写入。

## LLM 边界

反馈计划由 `feedback-plan-service` 统一负责范围、证据快照、模块依赖、偏好失效、任务事务、审批和导出；页面只调用 `/api/report/feedback-plans` 及其子路由。生成顺序固定为：服务从课次评价、事件、沟通、测验证据和已确认偏好构建 `FeedbackEvidenceBundle`；`feedbackDraft` 返回 `FeedbackCompositionPlan` 与初稿；`feedbackReview` 对同一证据包审核并受限润色；程序门禁检查来源引用、学生身份、模块依赖、家长动作、隐性承诺、内部内容和文本哈希。未批准条目不能进入 Excel。

`TeacherTask` 是未来教师动作的硬门禁；`TeacherObservation` 仅表示内部观察，不能解除承诺阻断。教师确认的教师处理会以 `Event.type = "教师处理"` 持久化，并在反馈计划证据中标记为已确认判断。沟通偏好候选由 Student Track 从已确认摘要或教师手工设置产生，教师确认前不改变当前偏好；WCG 不直接写入偏好标签。反馈附件写入仓库外私有目录，数据库只保存最小元数据和受控相对定位符。

LLM 负责提出解析结果和文本建议，不是业务事实来源。姓名映射、班级边界、未提及学生缺勤、分数范围和最终写入由确定性代码及教师确认控制。

教学总结由 `teaching-summary-service` 统一聚合，Route Handler 和页面不得直接拼接 Prisma 查询。GET 每次实时重算确定性事实；POST 每个课次或日期范围最多发起一次结构化模型请求。模型只收到短学生、课次和沟通编号，结果经服务端恢复并校验；未知引用或无来源结论整份拒绝。缓存同时绑定来源指纹、提示词版本、模型配置和是否纳入沟通，任何一项变化时旧解读不得与新事实混合显示。

教师沟通观察由独立 Service 持久化，只关联已经确认的 `Communication`。状态变化写系统日志但不改来源沟通；相同学生、观察类型和主题聚合，新来源证据可重新打开已关闭观察。该模型不参与 Dashboard 原有风险计算，面向家长的提示词和导出也不得读取它。

AI 生成历史由 `generation-memory-service` 实施热、温、长期三层保留。热转温只把经过业务校验的结果压缩到已确认学期快照，不调用模型；温转长期只能读取学期 `TeachingMemory.content` 中与到期生成记录对应的受控摘要，不能把 `GenerationRecord.warmSnapshot` 的计数、课次 ID 或压缩元数据当成教学证据。长期草案按班级由教师在“工作历史 → AI 生成”手动触发，来源指纹和 `MemoryCompactionRun` 保证幂等并记录失败；没有可靠摘要时不调用模型。热转温成功后的回滚数据最多保留 7 天，界面只展示仍可撤销的运行。已确认长期背景在 1.0 beta 仅供教师查看，反馈上下文 Service、家长预览、成稿和导出不得读取。

外部 LLM 失败只能使当前生成任务失败，不得修改已经保存的学生档案或历史记录。流式接口应使用统一 SSE 编解码工具，结束事件和错误事件必须可区分。

课后反馈生成必须先由 Service 组装确定性上下文，再由反馈分析模型生成仅供内部使用的趋势与历史草稿，最后由成稿模型对照原始确定性上下文复核并改写成家长可读文本。两次调用保存在本机 `data/llm-cache/` 的同一操作目录中；内部分析可以进入本机工作历史供教师查看，但不得导出为家长反馈，成稿失败时也不得回退使用内部分析。上下文可包含今日课次表现、近期趋势、家校沟通和学生标签；LLM 不能决定学生身份、课次边界、考勤补全、D 分或数据库写入。

反馈生成 Service 先调用分析角色，再将同一份确定性上下文与内部分析交给成稿审核角色。审核结果是通过、已修订或需人工确认；成稿 JSON 异常、最终文本为空或混入其他学生姓名时不采纳未知文本，只保留内部分析供教师查看并标记人工处理。两个角色在本地 LLM 配置中引用现有配置档案；未指定时都跟随当前激活档案，因此可以使用同一模型。密钥仍只保存在本机运行配置，不进入 Prisma 数据库。

## 音频转写边界

音频转写是 NL 录入的辅助输入，不是核心领域模型。转写任务、音频文件、日志和中间结果保存在 `data/diarize/`，不写入 Prisma 业务表；只有用户将转写文本送入 NL 录入并复核确认后，才可能产生正式的评价、考勤、事件或沟通记录。

Student Track 的本地转写入口通过项目根目录 `diarize.sh` 委托外部 FunASR 工具。项目入口负责选择 Student Track 适用的模型、纯转写模式和任务级热词；外部工具保留通用能力，不承担 Student Track 的学生名单或业务语义。

转写结果可用于提高录入效率，但不是事实来源。姓名匹配、未提及学生缺勤、课次边界和最终写入仍由 NL 解析后的确定性逻辑及教师复核控制。

## 历史与日志

- `SessionMetricHistory` 保存业务数据变更前快照，用于追溯评价。
- `WorkHistory` 保存可恢复的页面工作状态，由用户主动清理。
- `SystemLog` 保存关键操作摘要，失败不回滚核心业务。
- 数据库备份用于灾难恢复，不能由以上任一表替代。

## 文档边界

- `DOMAIN.md`：稳定术语、实体边界和不变量。
- `ARCHITECTURE.md`：分层、数据流和稳定工程约束。
- `OPERATIONS.md`：启动、迁移、备份、恢复和验证。
- `DECISIONS.md`：少数需要长期解释的重要选择。
- `generated/`：从代码生成的 Schema、路由和 ER 图，不手工维护。
- GitHub Issues：Feature、Bug、Refactor 和技术债等变化过程。
