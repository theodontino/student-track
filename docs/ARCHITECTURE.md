# 架构设计

## 目标

Student Track 是单人维护的本地优先课后反馈自动化工具。架构优先保证数据安全、业务规则可读和低维护成本，不为尚未出现的并发或组织规模预建基础设施。Web 服务只绑定 `127.0.0.1`；当前不支持局域网或公网部署，也不以缺少身份认证的状态对外暴露。

## 前端模块边界

App Router 页面只组合 Feature 工作台或执行兼容重定向。交互状态、请求和历史恢复归属 `src/features/`；通用控件归属 `src/components/ui/`，HTTP JSON 与文件下载归属 `src/lib/api-client.ts`。Feature 通过公开入口复用共享能力，不直接引用另一个 Feature 的内部文件。

学期、班级、课次采用显式 URL 上下文：`semesterId`、`classId`（同时保留可读的 `class`）、`sessionCode`。学期变化清空班级和课次，班级变化清空课次。班级选项必须从所选学期的 `/api/semesters/:id/classes` 读取，不能从全局学生列表猜测。URL 是当前页面的事实来源；标签页级 `sessionStorage` 只记录最近教学上下文，用于在工作台之间导航时补全 URL，不作为全局数据缓存。

未提交的页面工作状态使用带版本包装的标签页级 `sessionStorage` 保留，涉及教学数据的工作台按“页面 + 学期 + 班级 + 课次”隔离，避免把旧草稿恢复到另一课次。工作台只能通过 `src/lib/session-workspace.ts` 和对应 hook 读写，必须校验恢复数据，版本不匹配时放弃恢复。该存储只用于当前标签页的课堂文字、结构化草案和已解析 PDF 证据，不是长期历史；不保存 `File`/`Blob`。凭据、API Key 和录音流不得写入页面工作状态；浏览器无法安全恢复的本地文件必须在离页前提醒。已创建的转写任务只保留任务 ID，结果仍从服务端任务目录读取。

展示型 TSX 由 Playwright 覆盖关键工作流和窄屏导航；Vitest 的显式统计范围为 `src/app/api/**/*.ts`、`src/services/**/*.ts`、`src/lib/**/*.ts` 和 `src/features/**/*.ts`，并排除展示型 TSX、纯类型与入口文件。这样新增但尚未被测试加载的逻辑也会进入统计，页面从 `app/` 迁入 Feature 时不会改变覆盖率口径。逐版本覆盖率属于构建结果，保留在对应发布记录或 CI 报告中，不写入稳定架构文档。

AI 任务通过 `src/features/ai-workflow/` 的判别联合与 reducer 表达校验、生成、复核、保存、完成、失败和取消。页面刷新后，仍处于运行阶段的存档必须恢复为可重试的中断状态，不能假装后台任务仍在继续。该状态只记录任务名称、阶段、时间和安全提示，不保存凭据、文件或模型请求正文。

反馈计划状态由数据库驱动：计划保存教师可读名称、来源计划、`inputSnapshot`、输入指纹、条目状态、生成模式、累计运行耗时和生成失败摘要，条目保存起止时间及耗时。第一次进入规划后即形成可恢复的数据库草稿；页面以约 800ms 防抖自动保存，也提供显式保存和 `Command-S`。开始生成时冻结计划配置并让条目进入 `queued`，最多两条进入 `generating`。暂停先写 `pause_requested`，不再领取新条目，进行中任务完成后进入 `paused`；继续只处理队列项且暂停时间不计入运行耗时。页面通过计划详情轮询，刷新、断线或请求生命周期结束不影响已完成条目；进程重启后没有活动执行器的 `generating` 条目可重新入队。`sessionStorage` 只保留计划创建前的当前标签页录入草案。

快速评分的参考资料、课次协调和保存/历史职责分别由独立 hook 管理；页面组合 hook 不重复实现差异提交或 ref 协调。录音转写同样把浏览器录音、任务 API、任务列表和结果操作分离，服务端任务 ID 是跨页面恢复的唯一运行标识。

学生仪表的数字风险必须按单一学期、实际课次班级和同课次班均计算；未来课次、无课次评价和其他学期数据不得混入。前四次课的相对表现、第五次课后的近期评分回落与长期低于班均均由纯规则模块计算。近期评分回落比较最后 20% 有效课次与学生本学期个人总体平均，至少需要 5 次有效评价。已触发考勤提醒的学生不再进入上方学习风险候选和早期排名。全局内部关注标签只在当前自动解析学期作为一个定性条件参与叠加，不能改写历史学期结果。学生仪表和班级仪表都复用同一确定性 `/api/alerts` 数据，但分别展示学生风险与班级状态；班级概况和班级预警必须携带稳定 `classId`，不能用可重复的展示名称关联；仪表加载不得调用 LLM。

课堂录入仍可使用受控的内部关注原因枚举；WCC handoff 消费不生成或写入学生关注标签。所有家长反馈上下文必须先过滤 `AI内部关注：*`，不能依赖提示词要求模型自行忽略。

学生档案的学期四维平均和综合分由 Service 按请求批量聚合，列表和详情复用同一计算规则。该结果是可重建的展示数据，不写入数据库或浏览器缓存；修改评价、考勤或课次后，下次请求必须从原始记录得到最新结果。列表聚合禁止逐学生查询，只有真实规模验证超过既定性能阈值时才另行论证持久化缓存。

`StudentClassEnrollment` 是花名册和班级业务的唯一入口。学生列表、WCG 目录、批量反馈和自动流程必须显式带 `semesterId`，并由共享 Enrollment Service 过滤 `ACTIVE`；API 可以为兼容客户端投影返回 `classId`、`classCode`、`class` 和状态，但这些字段不再来自 `Student`。状态转换写安全系统日志，重复请求幂等；转班只更新当期归属，不删除、不回写且不重新解释任何历史业务数据。

班级组和共同讲次的成员关系、生命周期和历史关联由 `group-lesson-service` 统一校验，真实课次创建选项与事务写入由 `session-service` 负责。班级组保存同一学期的当前平行班关系和进度基准班（字段名 `leadClass`）；进度基准班只形成推荐，不是隐藏写入规则。组内创建 `ClassSession` 前必须显式提交三种意图之一：使用当前建议、指定一个 `GroupLesson`、或建立独立课次。建议查询是只读的：它以该班已关联的最高 `sequence` 为下界，不选取更早的缺口；其他班只建议向后跟进已开始的讲次，进度基准班则可建议进入更高的已有讲次，或在教师明确选择建议时建立下一讲草稿。缺少本班起点、日期倒序、最近独立课次或下一讲尚未开始时，服务不猜测，要求教师指定讲次或独立课次。课次、初始考勤和已选共同进度关联在同一事务完成；建课请求携带一次性幂等键，网络中断后的同内容重试返回原课次，同一键改用不同内容则拒绝。

`ClassGroupPanel` 是班级组共同进度的管理面：以共同讲次为行、当前成员班为列展示每个 `GroupLessonSession`，并单独列出组内未关联的真实课次。教师可以在这里关联、解除和改正共同进度，但不搬移 `ClassSession` 上的评分、考勤或事件。已关联课次的共同讲次冻结 `sequence`；尚无关联、无确认修订且未被反馈业务引用的误建草稿才可删除。历史课次以已保存的 `GroupLessonSession` 而不是当前 `ClassGroupMembership` 还原关系；已有历史关联只能保持原关联或在同一历史组内调整。

共同课保存可编辑材料和不可变的教师确认修订，真实授课继续使用各班自己的 `ClassSession`。学期话术库由 `feedback-script-library-service` 规范化为公共材料；明确建立的新共同讲次可形成同号材料草稿，但不自动确认。没有共同课的课次把教师明确选择的材料保存到 `ClassSession.commonMaterialSnapshot`；关联共同课后该快照不参与反馈解析。共同进度只关联对象，不读取或合并学生评分、考勤、事件或沟通；后续反馈只能读取已确认修订或明确的课次快照并复制快照，草稿不会自动影响其他班。

`feedback-plan-batch-service` 编排共同课的多个班级计划，并继续负责草稿保存、来源修订、历史读取、执行恢复、导出和归档。批次保存面向教师的名称、来源批次、共同课材料修订、默认输出要求和运行状态；每个子计划仍绑定一个真实班级和课次。班级可以覆盖默认输出要求与生成偏好，学生可以沿用既有条目级独立配置。批次服务不能跨班读取、合并或搬移事实和学生证据。

批次合并导出由 `feedback-export-service` 读取所有子计划中本次入选的已批准学生条目。工作簿不按班复制工作表，而是在反馈、教师研判、任务和附件表中统一增加班级编号与名称。写文件内容完成并计算 SHA-256 后，单一事务登记批次运行、子计划运行和条目导出状态；WCG 草稿包仍只允许从教师明确选择的单班计划生成，批次没有发送或跨班草稿接口。

统一课后任务由 `feedback-intake-service` 负责单课次材料整理；共同课模式在其上增加 `feedback-group-intake-service` 路由层，再把结果交给既有 `FeedbackPlan` 工作室。组路由层只读取共同课关联的真实课次和各班当前花名册：助教表按表内班级拆给对应课次，STEP 按班级编号路由，个人 PDF 按组内唯一学生身份和真实课次归属。路由完成后仍逐课次调用同一 Intake 服务，形成多个独立运行，不复制解析和确认规则。服务只在教师主动投料或扫描时读取文件；ZIP 解包内容只存在于当前请求。扫描阶段不写课堂事实；教师完成异常决策后，每个运行在事务中再次校验稳定 ID 并写入该班确认快照。主反馈的公共材料选择显式区分当前共同课修订、独立课次快照和 `none`；`none` 不回退到其他修订。确认的材料由服务按当前真实课次校验后带入，创建计划时复制到 `inputSnapshot`，不实时读取草稿。

助教表检查结果在同一 IntakeRun 快照中保存班级命中、学生行命中和课次核对三个阶段的确定性统计。学生异常决定以行级 issue ID 为边界；`skip_student` 只排除该行，`bind_student` 只绑定当前班候选，来源级 `accept_source` 只允许解决日期或课次边界。旧运行没有阶段字段时，客户端按既有 issue code 和 sourceFacts 还原展示，不要求重新上传原文件。

默认 `/feedback` 只有一套三段式控制器：录入、规划、生成。三个步骤始终可见，`view=intake|plan|studio` 只控制页面投影，刷新和演示链接都能恢复，而计划的 `status` 与 `generationStartedAt` 独立决定可编辑性。当前课次属于至少含两个真实课次的共同课时，教师可在录入页切换“本班”和“共同课”；共同课模式一次编排全部班级，但事实、范围和计划仍按真实课次分别保存。没有计划时录入页允许核验并写入事实；打开既有计划时录入页从其 V2 快照只读展示采用事实、材料来源、异常决策和确认时间，不实时重算旧计划。有效 `planId` 或 `batchId` 都投影到同一组三步视图，生成页继续复用 `FeedbackPlanStudio`，班级组工作室提供跨班学生导航。`/feedback/tools` 继续提供人工事实、PDF、公共材料、特殊计划和活动计划工具；`/feedback/advanced` 仅做兼容重定向。

当前学期优先选择日期范围覆盖今天且 `startDate` 最新的学期；无匹配时回退到拥有最近课次的学期，再回退到开始日期最新的学期。学生是否参与某学期由 `StudentClassEnrollment` 明确记录；升级旧数据时才从课次证据推导历史归属，历史班级归属以日期最新的课次为当前推导结果。

## 请求链路

```text
Page / Component
  -> Route Handler
    -> Service（复杂业务、事务、跨入口复用）
      -> Prisma
        -> SQLite
```

- 页面负责交互和展示，不直接访问 Prisma，不承载业务判断。
- Route Handler 负责输入解析、HTTP 状态和响应格式。
- 简单单表 CRUD 可以直接使用 Prisma。
- 多表写入、复杂规则、事务或多入口复用进入 `src/services/`。
- Repository 只在复杂查询被多个 Service 重复使用时建立，不作为固定层级。
- 教师或机构可能调整的规则进入 `src/config/`；数据库约束与稳定领域不变量保留在 Schema 或 Service。

所有外部输入在 Route Handler 边界使用 `src/lib/contracts/` 的 Zod schema 校验。课堂解析和转写的流式事件统一通过 `src/lib/sse.ts` 解码；格式错误、截断和取消不会被当作正常完成。反馈计划生成状态只从数据库读取，不把学生正文缓存到浏览器。

`src/proxy.ts` 只允许回环地址上的精确同源 API 请求；浏览器提供 `Origin` 时必须与请求 URL 的协议、主机和端口完全一致，不能把 `localhost`、`127.0.0.1` 和 `::1` 相互替代，也不接受 `Sec-Fetch-Site: same-site`。跨源、跨站或外部 Host 直接返回受控 `403`。缺少浏览器 Fetch 元数据的本机 CLI/测试请求仍可通过，但不放宽回环地址限制。生产服务仍只绑定 `127.0.0.1`，这层检查不能替代未来真正的身份认证。

## 渐进式多客户端兼容

当前 Web 是唯一已实现的 Student Track 客户端；没有明确版本的现有 Route 视为 Web 内部接口，不因此自动承诺给外部客户端。未来独立的 SwiftUI 客户端只能通过版本化回环 API 使用 Student Track 能力，不能直接读取数据库、Prisma 生成物、LLM 配置、缓存、附件或任务目录。跨客户端 Route 只承担协议适配，业务规则仍由与 Web 共用的 Service 实现。

兼容性按真实迁移的工作流逐条建立，不批量镜像全部 Route。新增或修改可能被多个客户端使用的能力时遵守以下约束：

- 请求、响应和文件清单具有版本化契约与合成 fixture；DTO 不直接暴露 Prisma 行或服务端绝对路径。
- 字段的空值、枚举、日期、排序和分页语义固定；新增字段保持旧客户端可忽略，改变既有语义时建立新版本。
- 错误采用稳定的机器可读代码，同时区分能否重试并提供不含敏感信息的诊断标识；客户端不依赖服务端异常文本判断流程。
- 可重复提交的写操作使用幂等键；可能覆盖教师修改的写操作同时校验修订号或等价前置条件。
- 长任务的事实状态保存在服务端持久层，客户端只持有任务 ID；刷新、客户端退出或网络中断不得把已完成结果变成未知状态。
- 文件契约明确 MIME、大小、哈希和受控定位符；客户端不得依赖服务端目录布局。
- 客户端先读取服务健康、协议版本与能力信息；不支持的能力隐藏、禁用或回退到 Web，不根据应用版本字符串猜测。

新建跨客户端接口时，Web 优先通过 `src/lib/api-client.ts` 的校验入口消费同一契约，以免 Web 和原生客户端形成两套响应解释。运行目录应逐步收口到统一的路径解析器，并允许由环境配置重定位；迁移已有目录必须保留兼容读取和明确的升级路径。

当前精确同源检查继续保护 Web，但不是原生客户端认证方案。原生调用凭据、端口发现、后端启动与退出、升级回滚及可分发打包必须在原生客户端阶段单独威胁建模和验证；未完成前不得通过放宽 Host、Origin 或跨源检查来接入原生客户端。

## 数据边界

`prisma/schema.prisma` 是数据库结构的唯一事实来源。Schema 变更必须通过 migration，并在全新数据库和现有数据升级路径上验证。

一次用户动作涉及多个核心写入时必须使用事务。例如确认录入草案时，评价、考勤、事件、沟通和草案状态要么共同成功，要么共同失败。操作日志属于辅助数据，可以在核心事务成功后独立写入。

## LLM 边界

提示词的硬边界、软引导、教师文本保护与修改方式统一遵循 [`PROMPTING.md`](PROMPTING.md)；不得把表达偏好不断升级为程序门禁，也不得在缺少明确授权时大规模重排教师已调整的提示词。

反馈计划由 `feedback-plan-service` 统一负责范围、课程材料快照、证据快照、录入来源摘要、草稿并发修订、来源克隆、模块依赖、偏好失效、任务事务、审批和导出；页面只调用 `/api/report/feedback-plans` 及其子路由。创建与启动生成是两个动作：草稿 `PATCH` 只在尚未生成时接受配置变化，启动时在同一持久化边界冻结快照，生成后只有显示名称可重命名；`clone_draft` 建立新行和新条目并保留来源 ID，不复制模型结果、正文、批准或导出账本。V2 输入快照保存本次事实包与所采用 IntakeRun 的来源摘要，旧 V1 和没有名称的记录仍可读取。生成顺序固定为：服务从冻结的课次评价、事件、沟通、测验证据和已确认偏好构建 `FeedbackEvidenceBundle`；其中个人测评通过独立 `assessmentEvidence` 通道进入，按课次与学生校验，旧证据快照缺少该字段时按空数组兼容。课程公共材料只写入 `teachingBackground`，不能被当成学生表现证据。教师最终文本可自动保存但仍需批准，未批准条目不能进入 Excel。

`TeacherTask` 是未来教师动作的硬门禁；`TeacherObservation` 仅表示内部观察，不能解除承诺阻断。教师确认的教师处理会以 `Event.type = "教师处理"` 持久化，并在反馈计划证据中标记为已确认判断。沟通偏好候选由 Student Track 从教师手工设置，或从 handoff 包内经过消息 ID 与逐字证据校验的结构化偏好信号产生；教师确认沟通草稿后才建立候选，确认候选前不改变当前偏好。摘要正则不作为 WCC 偏好的事实来源，WCG 也不直接写入偏好标签。反馈附件写入仓库外私有目录，数据库只保存最小元数据和受控相对定位符。

LLM 负责提出解析结果和文本建议，不是业务事实来源。姓名映射、班级边界、未提及学生缺勤、分数范围和最终写入由确定性代码及教师确认控制。

教学总结由 `teaching-summary-service` 统一聚合，Route Handler 和页面不得直接拼接 Prisma 查询。GET 每次实时重算确定性事实；POST 每个课次或日期范围最多发起一次结构化模型请求。模型只收到短学生、课次和沟通编号，结果经服务端恢复并校验；未知引用或无来源结论整份拒绝。缓存同时绑定来源指纹、提示词版本、模型配置和是否纳入沟通，任何一项变化时旧解读不得与新事实混合显示。

教师沟通观察由独立 Service 持久化，只关联已经确认的 `Communication`。状态变化写系统日志但不改来源沟通；相同学生、观察类型和主题聚合，新来源证据可重新打开已关闭观察。该模型不参与 Dashboard 原有风险计算，面向家长的提示词和导出也不得读取它。

AI 生成历史由 `generation-memory-service` 实施热、温、长期三层保留。热转温只把经过业务校验的结果压缩到已确认学期快照，不调用模型；温转长期只能读取学期 `TeachingMemory.content` 中与到期生成记录对应的受控摘要，不能把 `GenerationRecord.warmSnapshot` 的计数、课次 ID 或压缩元数据当成教学证据。长期草案按班级由教师在“系统中心 → 维护与日志”手动触发，来源指纹和 `MemoryCompactionRun` 保证幂等并记录失败；没有可靠摘要时不调用模型。热转温成功后的回滚数据最多保留 7 天，界面只展示仍可撤销的运行。已确认长期背景在 1.0 beta 仅供教师查看，反馈上下文 Service、家长预览、成稿和导出不得读取。

外部 LLM 失败只能使当前生成任务失败，不得修改已经保存的学生档案或历史记录。流式接口应使用统一 SSE 编解码工具，结束事件和错误事件必须可区分。

课后反馈生成必须先由 Service 组装确定性上下文，再由反馈分析模型生成结构化初稿。标准生成继续由成稿模型对照原始确定性上下文复核并改写；快速生成跳过这一步，把结构化初稿交给教师，但仍执行空正文、跨学生、未确认材料、证据覆盖、任务和结构规则等程序核验。调用保存在本机 `data/llm-cache/` 的操作目录中并写入 `GenerationRecord` 审计，但不得作为教师日常历史入口。上下文可包含今日课次表现、近期趋势、家校沟通和学生标签；LLM 不能决定学生身份、课次边界、考勤补全、D 分或数据库写入。

标准生成先调用分析角色，再将同一份确定性上下文与初稿交给成稿审核角色；快速生成只调用分析角色。标准审核结果是通过、已修订或需人工确认；JSON 异常会进入受控结构修复，最终文本为空、混入其他学生姓名或引用未确认材料时由程序核验阻断批准。两个角色在本地 LLM 配置中引用现有配置档案；未指定时都跟随当前激活档案，因此可以使用同一模型。密钥仍只保存在本机运行配置，不进入 Prisma 数据库。

反馈内容结构与表达参数相互独立。表达维度为“简洁 / 详细”和“温和 / 专业”；
字符数仅用于界面参考，不改变模型审核状态，也不阻止保存或导出。单人场景通过普通
FeedbackPlan 只选择一名学生完成，不再维护独立单人入口或模型版本选择链路；旧表达值在
读取时归一化，旧的纯长度越界状态不再构成导出阻断。

生成页复用全局 LLM 配置 API，只移动“分析模型”和“成稿与审核模型”两个选择器；企微提取模型仍在系统中心。实际使用模型写入 `GenerationRecord`，不增加计划级模型覆盖配置。`FeedbackPlanItem.selectedGenerationId` 直接指向当前条目的模型审计记录，教师最终编辑文本优先于模型输出；输入指纹变化时按计划快照重新取证，不从当前数据库猜测历史。

WCG 业务数据只通过 `wcc.student-track-file.v1` 进入。包不包含 ST 学生 ID、课次或
正式业务记录。ST 在本端校验路径、大小、Schema、SHA-256、包身份和幂等性，唯一匹配

ID；接口错误只返回受控代码，不返回模型正文、路径或内部异常。

所有实际发起的 LLM 任务按一次用户操作写入 `data/llm-cache/<上海日期>/<任务类型>/<操作 ID>/`。缓存保存请求、模型原始响应、推理内容和安全诊断，但不保存请求头或凭据；它是本机短期排障材料，不替代业务数据库、handoff 台账或不可变回执。缓存写入失败只能形成维护警告，不能改变业务事务结果；维护 API 只返回状态、次数、时间和大小等元数据。

WCG 是仓库外的独立工具，不属于 Student Track 源码或发布物；WCL 仅保留历史 OpenClaw 能力，不参与当前交付链。唯一在线边界是

## 音频转写边界

音频转写是 NL 录入的辅助输入，不是核心领域模型。转写任务、音频文件、日志和中间结果保存在 `data/diarize/`，不写入 Prisma 业务表；只有用户将转写文本送入 NL 录入并复核确认后，才可能产生正式的评价、考勤、事件或沟通记录。

Student Track 的本地转写入口通过项目根目录 `diarize.sh` 委托外部 FunASR 工具。项目入口负责选择 Student Track 适用的模型、纯转写模式和任务级热词；外部工具保留通用能力，不承担 Student Track 的学生名单或业务语义。

转写结果可用于提高录入效率，但不是事实来源。姓名匹配、未提及学生缺勤、课次边界和最终写入仍由 NL 解析后的确定性逻辑及教师复核控制。

## 历史与日志

- `SessionMetricHistory` 保存业务数据变更前快照，用于追溯评价。
- `FeedbackPlan` 是反馈流程和反馈历史的唯一权威来源；`archivedAt` 隐藏归档计划，已生成或已批准计划不能硬删除。
- `GenerationRecord` 只作为模型审计账本，不作为教师日常历史入口。
- `SystemLog` 保存关键操作摘要，失败不回滚核心业务。
- 数据库备份用于灾难恢复，不能由以上任一表替代。

## 文档边界

- `DOMAIN.md`：稳定术语、实体边界和不变量。
- `ARCHITECTURE.md`：分层、数据流和稳定工程约束。
- `OPERATIONS.md`：启动、迁移、备份、恢复和验证。
- `DECISIONS.md`：少数需要长期解释的重要选择。
- `generated/`：从代码生成的 Schema、路由和 ER 图，不手工维护。
- GitHub Issues：Feature、Bug、Refactor 和技术债等变化过程。
