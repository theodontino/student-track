# 用户体验与界面规范

## 产品气质

Student Track 是教师长期使用的本地教学工作台。界面采用深蓝灰画布、亮蓝功能色、克制紫色氛围和杏黄/琥珀提醒；高频编辑页保持紧凑，档案与分析页适当留白。半透明材质只用于建立清楚的空间层级，不能牺牲文字对比度或数据密度。

界面设计借鉴成熟管理后台的共同原则：导航位置稳定、信息层级清楚、表单错误靠近输入项、操作结果可见、键盘和窄窗口可用。不得直接复制其他产品的品牌外观。

## Web 基线与未来原生客户端

本文件是现有 Web 客户端的界面与交互基线。未来独立的 SwiftUI 客户端可以使用 macOS 原生控件、导航和视觉规范，不需要复制 Web 的页面模板、CSS token 或响应式布局；但必须保持相同的领域术语、业务状态、教师确认点、错误可恢复性、数据保护和无障碍目标。

原生客户端按工作流渐进替换。在某项能力完成版本化契约和原生验收前，Web 仍是该能力的兼容入口；不能为了界面迁移省略教师复核、批准、并发修改保护或“不发送”等现有门禁。两端共享后端 Service 与契约，不共享页面状态，也不由原生客户端直接读取数据库或服务端文件目录。

## 设计基础

- 只使用系统字体，不依赖在线字体资源。
- 正文使用 14px 或 16px，辅助信息使用 12px；页面、区块和控件标题必须形成稳定层级。
- 间距只从 4、8、12、16、24、32px 阶梯中选择，避免一次性数值。
- 圆角只使用 8、12、16px；阴影只区分静态表面和浮层两档。
- 深色主题中，蓝色承担品牌、链接、选中、主要操作和正向完成；紫色只用于背景氛围与少量强调；杏黄/琥珀承担关注和警告；红色只用于破坏性操作与真实失败。经典主题继续保留蓝、绿、琥珀、红的原状态语义。
- 状态不能只依靠颜色表达，必须同时具有文字、图标或可访问名称。
- 单个操作区只突出一个主要操作；危险操作使用明确文案并二次确认。
- 页面和控件过渡使用浏览器原生 CSS，通常控制在 120–320ms；运行态光晕仅在真实任务或待处理事项存在时呼吸，指针越靠近边框时局部增强。动画必须优先使用 `transform` 和 `opacity`，并尊重 `prefers-reduced-motion`。
- Emoji 不作为正式导航或操作图标。

颜色、间距、圆角和阴影必须引用 `src/app/globals.css` 中的语义 token。业务组件不得新增同义颜色常量或复制一套局部主题。

系统中心提供四套稳定配色：经典、暮蓝、星云和平衡星云。平衡星云为默认主题；选择只保存在浏览器 `localStorage`，不进入业务数据库。新增组件必须同时验证经典明亮主题和至少一套深色主题。

## 五种页面模板

每个页面必须采用以下一种模板，不新增第六套页面骨架：

1. **概览页**：学生仪表与班级仪表。根路径默认显示学生仪表，先显示警告和教师待办，再显示状态与摘要；班级仪表独立展示班级预警和四维概况。
2. **高频工作台**：快速评分、课后工作台、教学总结和转写。课后工作台统一准备、录入、复核、生成和导出；上下文与主要操作稳定可见，步骤可自由切换且恢复时不丢失内容。
3. **列表管理页**：学生、反馈历史和导出。由页面标题、筛选工具栏、结果区和明确的空状态组成。
4. **档案详情页**：学生和学期详情。身份摘要保持稳定，分析与历史记录分区展示。
5. **系统页**：配置、集成和维护。共享系统子导航，不合并为一个巨大客户端页面。

页面宽度按工作类型选择：概览与详情使用舒展的受限宽度；多列编辑工作台可以使用更宽画布；正文不得无理由贴满超宽屏。

## 教学上下文与页面连续性

- 学期、班级和课次以 URL 参数为事实来源，页面之间跳转时继续携带。
- 学期变化清空班级和课次，班级变化清空课次。
- 可恢复的筛选、草稿和工作状态使用带版本与运行时校验的标签页级 `sessionStorage`。
- 涉及教学数据的草稿必须按页面、学期、班级和课次隔离。
- 页面恢复后显示已恢复状态；不得把另一个课次的草稿静默带入当前页面。
- 反馈生成中断后必须显示计划级队列统计、已完成数量和失败条目；已完成结果继续可见。暂停、继续和失败重试是独立操作，状态来自 `FeedbackPlan` 数据库记录。
- API Key、Token、File、Blob、音频和凭据不得写入页面恢复数据。
- 无法恢复的本地文件在离页前必须提醒。

## 操作与状态反馈

加载、空数据、部分数据、错误、成功和危险操作使用共享 UI 组件。保存型工作流统一表达以下状态：

```text
未修改 → 有修改 → 保存中 → 已保存
                  ↘ 保存失败（保留修改并允许重试）
```

AI 工作流统一表达以下状态：

```text
等待 → 校验 → 生成 → 待复核 → 保存 → 完成
                ↘ 失败 / 已取消（保留安全输入并允许恢复）
```

不得使用假进度百分比。外部 LLM 或本地工具失败不能让已经成功保存的业务数据显示为失败。

## 表单、浮层与数据展示

- 表单项统一包含 label、可选说明、错误和必填状态；错误显示在对应字段附近。
- Dialog 用于短任务，Drawer 用于不离开当前上下文的详情或较长任务。
- 学生列表使用“名单 + 轻量检查器”：精确指针悬停 120ms 后预览，离开时先播放反向滑动渐出再恢复空状态；点击直接打开完整档案。触摸设备不依赖悬停。
- 学生列表始终可查看全部历史档案，并提供在读/非活跃筛选、状态徽标、生效时间以及停用/恢复操作；状态操作不能复用删除确认或让历史记录消失。
- 学生综合分排序只在班级内进行，默认由高到低；缺失分数始终置底，不显示排名数字或建立跨班排行榜。
- Dialog 和 Drawer 必须支持 Escape、焦点进入与返回、背景滚动锁定和可访问标题。
- 表格和列表必须有加载、空数据与失败状态；操作列不能只显示含义不明的图标。
- 长日志表格使用受限高度的内部滚动容器和粘性表头，避免一次加载几十行时无限拉长整个页面。
- 反馈历史默认只显示非归档 `FeedbackPlan`，支持学期、班级、课次、学生、课程日期、状态和归档筛选；恢复链接携带 `planId` 与教学上下文。
- 课后工作台顶部使用紧凑的当前计划栏，展示名称、班级/课次、单班或班级组、配置生成方式、进度、legacy 只读状态和当前唯一主要操作；其他计划通过“切换计划”Drawer 打开。Drawer 默认只查当前学期，支持名称与班级搜索，当前 Plan/Batch 置顶且不重复，Batch 只显示一行，其余按“正在生成”“需要继续”“最近完成”分组，最近完成只显示最新五项并默认折叠，同时保留完整反馈历史入口。
- 图表必须说明时间范围、样本数量和缺失数据，不能把缺失值画成零。
- 综合分、预警和 AI 结论必须展示足以解释结果的上下文，不把颜色当作结论。
- 快速评分与课后材料准备页必须显式解释四个维度：A 为学习与测验，B 为精神与纪律，C 为课后任务，D 为系统按考勤计算；同时显示个人出门测唯一匹配后“A = 正确率 ÷ 20，保留一位小数”的规则。自动得到的小数 A 必须可见，不能因整数快捷按钮而表现成未选中或丢失。
- 材料异常弹窗的单项选择与批量操作使用同一组策略定义；当当前弹窗内至少两项可以安全采用同一答案时提供一键操作，并明确批量操作只保存选择、仍需底部确认才写入课堂事实。身份绑定、同一学生多份 PDF 等每项答案不同的异常不得批量猜测。
- 学生仪表将“警告学生”“教师待办”“持续关注”“考勤提醒”“家校沟通观察”和摘要按行动优先级纵向排列；警告使用红色，持续关注使用杏色，考勤提醒使用亮蓝色。教师待办的逾期、今日、下次课和更晚任务直接展示，已完成与已取消任务默认折叠到任务历史。持续关注再按“状态回落”“表现观察”“定性反馈”分栏，窄屏时纵向堆叠；每栏各自最多默认展示五人，并由一个按钮统一展开或收起三栏。每名学生只出现一次，并展示触发条件及可解释证据。
- 班级仪表独立展示班级状态卡，红色预警班级、黄色预警班级排在正常班级之前，再显示班级数、预警班级数和预警维度数；不重复显示学生风险、教师待办、考勤提醒或家校沟通观察。
- 教学总结将“确定性事实”“AI 教师解读”和“家校沟通观察”分成独立区域。确定性事实无需模型即可查看；模型只在教师明确点击后运行。家校沟通观察使用亮琥珀色并独立于警告、关注和考勤计数，默认最多展示五项后再展开。
- 系统中心的本地工具默认只显示状态摘要、风险和建议；路径与逐项检查收起在可访问的详情区域。WCG 只检查交换目录和花名册 API 配置；“企微家校”独立工作区只保留中转仓库与教师复核，反馈工作台仅保留跳转入口。
- 反馈生成页显示分析模型、成稿与审核模型、计划的受限/自由生成方式、条目实际执行方式、总耗时、平均每生、生成速度、逐条耗时、队列、进度、暂停、继续和失败重试；企微提取模型留在系统中心。受限反馈失败时可以显示“改用自由反馈”，但必须在明确确认后才改变失败或未开始条目，已成功结果不重写；legacy 历史计划明确显示停止继续生成，并提供“另存为新计划”入口。生成完成后停留在生成页并保留计时，可由教师进入复核。
- 逐学生复核区固定按“当前状态—教师最终正文—计划内容—学生事实—学生趋势—高级选项”排列。状态区只保留当前对象、队列位置、配置方式、实际方式、核验结果和唯一主要操作；核验通过只显示一行，问题项就近展示影响、建议和教师任务入口。最终正文全宽并占首屏主要画布；计划内容与事实保持确定性事实、模型建议的语义分离，趋势全宽且说明范围、样本与缺失数据；技术核验码、生成轨迹、模型初稿、任务历史和附件默认折叠。Excel、企微 JSON、归档等计划级操作统一放入计划工具栏。
- 正文采用约 800ms 防抖自动保存并保留手动保存按钮；无新修改时显示“已保存”并禁用，使用条目修订号避免覆盖并发修改。批准或导出后的正文只读，教师最终文本是导出唯一权威。
- handoff replacement/correction 使用可辨识徽标；谱系不完整只在接收与诊断区展示，不伪装成普通待确认沟通。
- 系统中心使用同一层级的页签呈现外观、模型、集成、维护、关于和开源许可；关于页说明产品与数据边界，许可页直接显示仓库根目录的 LICENSE，不把许可摘要散落为另一套视觉组件。
- 需要谨慎的丢弃、回执修复和忽略操作使用亮琥珀色风险按钮；红色只用于已经发生的错误和真正的危险删除语义。回执修复必须先展示只读预检，并要求输入确认文本。

## 响应式与可访问性

- 以桌面为主要编辑环境，在 900px 以下切换为抽屉导航。
- 720px 宽度必须能够完成导航、查看档案和核心教学工作流。
- 课后工作台在桌面保留左侧学生队列；窄屏把学生选择改为 Drawer。720px 下必须能够选择学生、查看核验、编辑正文、保存、批准并进入下一名学生，且计划工具栏允许换行而不产生页面整体横向溢出。
- 不承诺手机宽度下的完整批量编辑，但不得出现无法关闭的浮层或横向页面整体溢出。
- 所有交互控件必须有键盘焦点和可访问名称；点击区域不得小于约 36px。
- 窄窗口不得通过隐藏主要操作来解决布局问题，应改为换行、纵向排列或固定操作栏。

## 代码约束

- Route 页面只组合 Feature；展示组件不承载复杂请求、SSE、历史恢复或业务规则。
- 通用 UI 不依赖业务 Feature。跨 Feature 复用只能通过公开导出。
- 不新增 `any`，不建立第二套 Student、Semester、Session、Draft 或 Feedback 类型。
- 大型页面按真实职责逐步拆分，不为了行数制造无意义文件。
- 新 UI 必须复用语义 token 和共享组件。一次性 Tailwind 样式只用于明确的业务布局，不复制按钮、输入框、状态或浮层外观。
- 当前标签页的版本化 `sessionStorage` 仅保留未提交课堂文字、结构化草案和已解析 PDF 证据；`FeedbackPlan` 是反馈历史唯一权威。Excel 与 WCG 文本草稿格式保持不变，旧历史页入口重定向到 `/review` 或系统维护页。
