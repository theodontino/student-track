# 领域模型

Student Track 用于校外教学机构围绕学生生成和追踪课后家校反馈。系统会记录学生、课次、课堂评价、考勤、关键事件和家校沟通，但产品价值不只是记录，而是降低自然语言录入、沟通信息整理和反馈草稿生成的摩擦。领域术语以本文件和 `prisma/schema.prisma` 为准；页面文案可以更口语化，但不应创造含义相近的新概念。

## 核心术语

| 中文术语 | 代码实体 | 含义与边界 |
|---|---|---|
| 班级 | `Class` | 稳定的教学分组。`code` 是唯一业务编号，`name` 是展示名称。 |
| 学生 | `Student` | 学生基础档案。必须属于一个班级，`studentId` 是唯一学号；`rosterStatus` 只表示当前自动处理资格，不重新解释历史。 |
| 学期 | `Semester` | 一段教学周期，包含起止日期和多个课次。 |
| 课次 | `ClassSession` | 一次实际教学活动。属于一个学期；可属于一个班级，`classId = null` 表示全校课次。 |
| 课次评价 | `SessionMetric` | 某学生在某课次的 A/B/C/D 四维评价，不是考试成绩总表。 |
| 考勤 | `Attendance` | 某学生在某课次是否出勤。每个学生、课次最多一条。 |
| 关键事件 | `Event` | 课堂表现、测验表现、心理状态等值得长期保留的事实。 |
| 家校沟通 | `Communication` | 围绕学生和课次、且对后续教学反馈有持续价值的沟通摘要；外部导入可用 `sourceKey` 保存稳定去重身份。收悉、寒暄、排课、缴费、接送和文件发送不属于学生档案。 |
| 录入草案 | `DraftRecord` | NL 解析或 handoff 后等待教师确认的临时业务草案；修订可为 replacement 或 correction，并显式关联被取代草案和原沟通。 |
| 评分变更历史 | `SessionMetricHistory` | 课次评价更新或删除前的不可变快照。 |
| 页面工作历史 | `WorkHistory` | 手动评分、录入、报告、导出等页面状态快照，不是学生档案。 |
| 系统日志 | `SystemLog` | 用于追踪关键系统操作，不参与业务计算。 |
| 教学总结缓存 | `TeachingSummaryCache` | 某个课次或日期范围的教师内部 AI 解读缓存；确定性事实始终实时重算。 |
| 教师沟通观察 | `TeacherObservation` | 从已确认家校沟通与课堂事实中形成的可追溯教师待办，不是学生风险或家长反馈。 |
| 观察来源 | `TeacherObservationSource` | 教师沟通观察与已确认 `Communication` 的来源关系。 |
| AI 生成记录 | `GenerationRecord` | 业务校验成功后的本地 LLM 结果账本；保存模型配置身份、输入修订、父版本和受控重放快照，模型原始结果不可变。 |
| 反馈版本选择 | `FeedbackGenerationSelection` | 某课次、某学生当前明确采用的生成版本；派生版本不会自动替换。 |
| 反馈计划 | `FeedbackPlan` | 教师手动启动的一次班级公共、事件微反馈、阶段趋势或结课教学总结工作流；不包含续班或服务适配判断。 |
| 反馈计划条目 | `FeedbackPlanItem` | 反馈计划中的一条班级文本或一名学生文本，保存版本化证据包、可选模块、审核结果、最终文本和批准/导出状态。 |
| 教师任务 | `TeacherTask` | 经教师批准、与反馈未来表述对应的可执行动作；`TeacherObservation` 不能替代任务。 |
| 沟通偏好 | `CommunicationPreference` | 教师确认的学生家庭表达偏好，只影响长度、证据呈现、术语和候选排序，不改变事实或服务边界。候选先存于 `CommunicationPreferenceCandidate`，不自动覆盖当前偏好。 |
| 反馈附件 | `FeedbackAttachment` | 教师明确标记为发送附件后，复制到仓库外私有 Application Support 目录的文件元数据；数据库只保存受控相对定位符、大小和 SHA-256。 |
| 反馈导出运行 | `FeedbackExportRun` | 一次完整或部分 Excel 导出的不可变条目清单、最终文本哈希和时间，用于补导和重复提醒。 |
| 沟通修订 | `CommunicationRevision` | 教师确认 correction 时保存的正式沟通更新前后快照及来源谱系。 |
| 教学记忆 | `TeachingMemory` | 从旧生成记录压缩得到的学生或班级学期快照，以及经教师确认的长期教学背景。 |
| 记忆压缩账本 | `MemoryCompactionRun` | 热数据转学期快照、学期快照转长期背景的可撤销处理记录。 |

## 评分语义

| 维度 | 含义 | 数据来源 |
|---|---|---|
| A | 学习目标达成与课堂测验表现 | 教师或经教师复核的 LLM 结果 |
| B | 精神面貌与课堂纪律 | 教师或经教师复核的 LLM 结果 |
| C | 课后任务 | 教师或经教师复核的 LLM 结果 |
| D | 考勤表现 | 系统根据当前学期考勤计算 |

四个维度当前均使用 0 到 5 的整数。`SessionMetric` 应优先绑定课次；`sessionId = null` 只用于兼容无课次来源，不应成为新功能的默认写入方式。

学生档案中的“学期综合分”是从原始记录实时计算的派生视图，不是考试成绩或新的持久化实体。A/B/C 分别取所选学期已发生课次的评价平均值；D 根据该学生在所选学期已有的明确考勤记录计算。缺少考勤记录不等于缺勤，未来课次不参与统计。四项完整时相加得到 20 分制综合分，再换算为百分制；任一数据类别缺失时显示数据不足，不写入或猜测总分。

## 领域约束

- 学生必须属于已存在的班级。
- inactive 学生默认不进入未来课次名单、批量反馈、当前风险、WCG 花名册和日期导出；历史评价、考勤、事件、沟通和手动档案查看保持不变。
- 课次必须属于已存在的学期；班级课次只能评价该班学生，全校课次可以覆盖所有学生。
- 同一学生、同一课次最多一条课次评价和一条考勤。
- A/B/C 由教师确认，D 由系统计算；LLM 不直接决定 D。
- NL 录入选择班级课次后，花名册中未被提及的学生按缺勤处理。
- 课次评价被更新或删除前，应追加 `SessionMetricHistory`，不能覆盖旧历史。
- 页面工作历史恢复只改变页面状态，不直接写入学生、评价、事件或考勤。
- 日志、页面历史等辅助写入失败，不应把已经完成的核心业务写入显示为失败。
- WCG handoff 只有在路径、大小、Schema、SHA-256、包身份和幂等性都通过后才登记；唯一匹配学生后才允许二次提取，否则进入人工匹配或受控失败状态。
- 二次提取必须有可追溯证据，并明确属于学习进步、具体困难、学习习惯、学习方法、学习信心、家长关切、反馈偏好、教师承诺或临时学习背景之一；低价值和无关记录标记为无有效内容，不创建 `Communication`。
- handoff 包不携带 Student Track 学生 ID、课次或正式业务记录。只有教师在 `DraftRecord` 中选择实际课次并确认后，才写入正式 `Communication`。

## 暂不新增的概念

`Exam` 目前不是独立领域实体。“测验”可记录为 A 维评价的一部分或 `Event`。只有当测验具有独立名称、日期、满分、参与名单、成绩集合和修改流程时，才论证新增 `Exam`。

`Score` 也不是独立实体。代码和文档应使用“课次评价”指代 `SessionMetric`，使用“维度分数”指代其中的 A/B/C/D 字段。

## 辅助模型

`Label`、`StudentLabel` 用于学生分类；`DraftRecord`、`WorkHistory`、`SystemLog` 和 `SessionMetricHistory` 支持业务流程与追踪，但不改变学生、班级、学期、课次、评价和考勤构成的核心领域。

`WeComImportState`、`WeComImportRun`、`WeComImportOperation`、
`WeComMessageReceipt` 和 `WeComImportChange` 是旧集成的只读历史账本，不是学生档案。
新代码不再活动写入、运行或回滚这些记录，本次解耦不删表、不改行。

`WeComHandoffPackage` 是 WCG 本地文件转交账本，只保存来源、包 ID、文件哈希、
处理状态和可选的匹配学生，不复制聊天正文。文件包和安全回执位于 Git 仓库外的
中立 Application Support 目录；正式沟通仍只在教师复核并绑定课次后产生。

`AI内部关注：*` 是教师内部使用的全局学生标签。已确认的课堂文字可以添加“成绩表现、学习信心、家长担心、退班意向”四类受控标签；WCG handoff 消费不创建这些标签。多个内部标签在仪表盘中只构成一个独立的“定性反馈”条件；它们不得进入家长反馈提示词、预览或导出，也不参与任何评分计算。

教学总结是实时确定性事实与可失效 AI 解读的组合视图。数字、完整度、出勤和状态变化只能由代码计算；模型不得计算或改写事实。教师沟通观察只使用已确认 `Communication`，以学生、观察类型和主题聚合。相同证据不重复创建；出现新证据时，已处理或已忽略的观察重新成为“新发现”。观察状态不修改来源沟通，也不进入学生风险、评分或对外反馈。

AI 生成历史采用三层保留：每班最近五次已完成课次保留完整的业务输入/输出快照；更早但未满六个月的记录压缩为不可全盘复原的学期快照；来源课次满六个月后只保留教师确认的长期教学背景与最小审计账本。热转温不调用模型，温转长期背景只读取已确认学期快照中的受控摘要，按班级手动批量生成草案并需要教师确认；没有可靠摘要时必须跳过。1.0 beta 的长期背景只在教师工作区内部展示，不进入家长反馈 prompt、预览、成稿或导出。原始企微聊天、模型思维内容、凭据和供应商原始协议永不写入这些表。

仪表盘的学生风险是实时派生视图，不写入数据库：前四次课以早期相对表现作为一个数字条件；第五次课起改用近期评分回落和长期低于同期班均。近期评分回落以最后 20% 有效课次和本学期个人总体平均之间的差距判定。一个独立条件显示“关注”，两个及以上显示“警告”。考勤提醒学生只在考勤区展示，不再进入上方学习风险排名；班级状态仍独立展示。

## 反馈上下文

课后反馈上下文不是新表，而是从现有领域模型临时组装出来的视图。它可以包含：

- 本课次的 `SessionMetric`、`Attendance` 和 `Event`。
- 近期若干课次的评价趋势和关键事件。
- 最近且仍有效的 `Communication`，包括企微导入的反馈上下文摘要。按实际沟通时间由近到远使用，新信息覆盖旧信息；历史噪声记录不会进入反馈 Prompt。
- 学生已有标签。

反馈上下文只服务于生成和预览，不直接写回数据库。若上下文中出现错误，应修正原始学生记录、课次评价、事件、沟通或标签，而不是为上下文本身新增修补字段。

反馈强度是本次生成策略，不是学生画像或新的领域状态：系统只用当前学期 Dashboard 的学习风险与目标课次前 21 天内未关闭的教师沟通观察，分为常规、轻关注和重点关注；考勤提醒不参与。常规反馈采用短、描述性的单次生成；轻关注和重点关注保留内部分析与审核。教师可对当前批次临时改档或设为人工确认，该选择仅随页面工作状态和 `WorkHistory` 保存，不改变后续课次、风险或观察。内部原因、观察正文和风险标签不得进入家长话术或导出。

群反馈和统一出门测说明属于“课程公共材料”：它们只能说明本节教了什么、测了什么以及统一订正建议，不能证明某个学生已经掌握或出现错误。可一次选择本机报告文件夹：系统先用当前课次班级名单匹配文件名，提示缺少报告，忽略其他班学生和无关文件，再以最多两份并发解析。个人出门测 PDF 经本机解析后可以提供该生本次正确率、知识点和错题证据；课程材料内部绑定课次，PDF 证据同时绑定课次与学生，服务端拒绝跨课次或跨学生混用。原始 PDF 不保存，提炼后的带绑定证据只随当前反馈工作状态和工作历史使用，不成为新的考试实体。

趋势表达不比较“前两次与最近两次”。最近两次有效 A 维评价同时对照该生本学期整体常态和各自课次的同期班均；个人记录不足三次或同课次有效学生不足三人时省略对应结论。对照结果用于解释近期状态，不输出排名，也不修改原始评价。

## 反馈计划

反馈计划采用三层流水线：确定性证据提取、可选模块组装与初稿、LLM 审核润色加程序硬门禁。教师手动创建计划；系统只推荐类型、候选学生和默认范围。个人反馈不是固定五段模板：教师可从具体表现、教师判断、教师处理、处理结果、家长最低动作和后续观察中选择两到四个有价值模块。表现良好可以只停在具体认可；家长动作只有真实需要时出现。

四类计划的边界固定为：`class_update` 只提供班级公共教学信息；`event_micro` 处理单个事件；`stage_trend` 汇总阶段起点、趋势和断点；`course_end` 只写教学总结和下一阶段学习路径，不生成续班、销售或服务适配结论。处理结果必须有已确认的 `Event.type = "教师处理"`；后续观察必须关联 `TeacherTask`。没有任务不得把“下次继续观察”等未来动作写进家长文本。教师直接修改最终文本时不再调用模型，只重新执行程序门禁并要求重新批准。
