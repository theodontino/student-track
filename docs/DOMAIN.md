# 领域模型

Student Track 用于校外教学机构围绕学生生成和追踪课后家校反馈。系统会记录学生、课次、课堂评价、考勤、关键事件和家校沟通，但产品价值不只是记录，而是降低自然语言录入、沟通信息整理和反馈草稿生成的摩擦。领域术语以本文件和 `prisma/schema.prisma` 为准；页面文案可以更口语化，但不应创造含义相近的新概念。

## 核心术语

| 中文术语 | 代码实体 | 含义与边界 |
|---|---|---|
| 班级 | `Class` | 某个学期内的教学分组。`code` 只在同一学期内唯一，`name` 是展示名称；不同学期创建不同班级实体和 ID。删除先写入 `deletedAt` 并进入 30 天回收站。 |
| 学生 | `Student` | 跨学期稳定的个人档案。`studentId` 是唯一学号；学生不保存全局班级或花名册状态。 |
| 学期 | `Semester` | 一段教学周期，包含起止日期、班级和多个课次。删除先写入 `deletedAt` 并使所属业务范围整体不可用。 |
| 学期班级归属 | `StudentClassEnrollment` | 学生在某学期的唯一班级归属及 `ACTIVE`/`INACTIVE` 花名册状态；转班只更新当前归属并保留历史课次。 |
| 班级组 | `ClassGroup` | 同一学期内共享课程进度的一组平行班；组内指定一个进度基准班（字段名 `leadClass`）形成后续建议，不自动替任何班建立或关联真实课次。每个班只有一个当前班级组，换组不改写历史课次关联。 |
| 共同课 | `GroupLesson` | 班级组计划共同完成的一讲公共教学材料；教师确认后形成不可变修订，各班真实教学仍由独立 `ClassSession` 表示。 |
| 共同课课次关联 | `GroupLessonSession` | 共同课与某班真实课次的教师确认关系，记录同步状态、差异说明和是否可比较，不合并评分、考勤或事件。 |
| 学期公共材料库 | `Semester.feedbackScriptLibraryJson` | 教师为一个学期一次上传、按课次复用的结构化群反馈、统一测评说明和私反馈模板（原话术库）；它是表达材料，不是学生事实或续班判断。 |
| 课次 | `ClassSession` | 一次实际教学活动。属于一个学期；可属于一个班级，`classId = null` 表示全校课次。 |
| 课次评价 | `SessionMetric` | 某学生在某课次的 A/B/C/D 四维评价，不是考试成绩总表。 |
| 考勤 | `Attendance` | 某学生在某课次是否出勤。每个学生、课次最多一条。 |
| 关键事件 | `Event` | 课堂表现、测验表现、心理状态等值得长期保留的事实。 |
| 家校沟通 | `Communication` | 围绕学生和课次、且对后续教学反馈有持续价值的沟通摘要；`occurredAt` 单独保存可靠的实际发生日期或跨日范围，`sessionId` 只表示教师确认后的业务谱系，不把跨日证据压成课次日期；外部导入可用 `sourceKey` 保存稳定去重身份。收悉、寒暄、排课、缴费、接送和文件发送不属于学生档案。 |
| 录入草案 | `DraftRecord` | NL 解析或 handoff 后等待教师确认的临时业务草案；修订可为 replacement 或 correction，并显式关联被取代草案和原沟通。 |
| 评分变更历史 | `SessionMetricHistory` | 课次评价更新或删除前的不可变快照。 |
| 系统日志 | `SystemLog` | 用于追踪关键系统操作，不参与业务计算。 |
| 教学总结缓存 | `TeachingSummaryCache` | 某个课次或日期范围的教师内部 AI 解读缓存；确定性事实始终实时重算。 |
| 教师沟通观察 | `TeacherObservation` | 从已确认家校沟通与课堂事实中形成的内部待办；复核页教师观察沿用 `Event(type="教师处理")` 进入反馈证据，不新增表或数据类型。 |
| 观察来源 | `TeacherObservationSource` | 教师沟通观察与已确认 `Communication` 的来源关系。 |
| AI 生成记录 | `GenerationRecord` | 业务校验成功后的本地 LLM 结果账本；保存模型配置身份、输入修订、父版本和受控重放快照，模型原始结果不可变。 |
| 反馈计划 | `FeedbackPlan` | 一份可命名、可恢复的班级公共、事件微反馈、阶段趋势或结课教学总结方案；保存生成所用事实与设置的快照，生成开始后内容冻结。`outputRequirement` 保存教师本次自然语言反馈要求，不包含续班或服务适配判断。 |
| 反馈计划批次 | `FeedbackPlanBatch` | 一份可命名的共同课多班规划及执行编排；共享默认反馈策略，但各班证据、学生、附件、正文、批准和导出始终属于独立 `FeedbackPlan`。 |
| 反馈材料运行 | `FeedbackIntakeRun` | 教师打开课后任务后，对收件箱、拖拽文件或 ZIP 的一次材料账本；保存来源、确定性事实摘要、异常、决策，以及教师确认的班级/课次/学生范围。事实确认和范围确认彼此独立，不保存原始文件，也不触发批准、导出或发送。 |
| 反馈计划条目 | `FeedbackPlanItem` | 反馈计划中的一条班级文本或一名学生文本，保存版本化证据包、可选模块、审核结果、最终文本和批准/导出状态；`selectedGenerationId` 是当前采用的模型审计记录。 |
| 教师任务 | `TeacherTask` | 经教师批准、与反馈未来表述对应的可执行动作；`TeacherObservation` 不能替代任务。 |
| 沟通偏好 | `CommunicationPreference` | 教师确认的学生家庭表达偏好，只影响长度（含长短均可）、文字/语音形式、微信电话接受、证据呈现、术语和候选排序，不改变事实或服务边界。企微候选必须来自家长显式回答并逐字段绑定 incoming 消息证据，先存于 `CommunicationPreferenceCandidate`，不自动覆盖当前偏好。 |
| 反馈附件 | `FeedbackAttachment` | 教师明确标记为发送附件后，复制到仓库外私有 Application Support 目录的文件元数据；数据库只保存受控相对定位符、大小和 SHA-256。 |
| 反馈导出运行 | `FeedbackExportRun` | 一次完整或部分 Excel 导出的不可变条目清单、最终文本哈希和时间，用于补导和重复提醒。 |
| 反馈批次导出运行 | `FeedbackPlanBatchExportRun` | 一次跨班 Excel 导出的不可变学生条目清单、工作簿哈希和子计划导出关系；单班导出不排除条目进入一次批次导出。 |
| 沟通修订 | `CommunicationRevision` | 教师确认 correction 时保存的正式沟通更新前后快照及来源谱系。 |
| 教学记忆 | `TeachingMemory` | 从旧生成记录压缩得到的学生或班级学期快照，以及经教师确认的长期教学背景。 |
| 记忆压缩账本 | `MemoryCompactionRun` | 热数据转学期快照、学期快照转长期背景的可撤销处理记录。 |

## 评分语义

| 维度 | 含义 | 数据来源 |
|---|---|---|
| A | 学习目标达成与课堂测验表现 | 教师、经教师复核的 LLM 结果，或唯一匹配个人出门测的正确率换算 |
| B | 精神面貌与课堂纪律 | 教师或经教师复核的 LLM 结果 |
| C | 课后任务 | 教师或经教师复核的 LLM 结果 |
| D | 考勤表现 | 系统根据当前学期考勤计算 |

A 使用 0 到 5 分并允许一位小数，B/C/D 使用 0 到 5 的整数。个人出门测 PDF 唯一匹配当前课次学生后，报告正确率是确定性事实，A 按“正确率 ÷ 20”换算并四舍五入保留一位小数，例如 83% 对应 4.2；该换算不需要逐生批准。同一学生同一维度出现不同分数时，不自动判断来源高低，而是在事实确认页展示来源和值，由教师选择一个候选；已有课堂评分时也可明确保留现有值，首次建立评分则必须选择实际候选。相同分数直接合并，但同一学生存在多份个人 PDF 时仍须选择本课采用的单份证据。只有 A 且该课次尚无评价时，沿用现有完整四维评价的中性基线，为 B/C 建立 3 分；若已有评价则保留既有 B/C。身份或课次无法唯一确定时仍进入异常处理。`SessionMetric` 应优先绑定课次；`sessionId = null` 只用于兼容无课次来源，不应成为新功能的默认写入方式。

学生档案中的“学期综合分”是从原始记录实时计算的派生视图，不是考试成绩或新的持久化实体。A/B/C 分别取所选学期已发生课次的评价平均值；D 根据该学生在所选学期已有的明确考勤记录计算。缺少考勤记录不等于缺勤，未来课次不参与统计。四项完整时相加得到 20 分制综合分，再换算为百分制；任一数据类别缺失时显示数据不足，不写入或猜测总分。

## 领域约束

- 学生在需要参与班级业务的学期必须有该学期的唯一 `StudentClassEnrollment`，且归属班级必须属于同一学期。
- inactive 归属默认不进入未来课次名单、批量反馈、当前风险、WCG 花名册和日期导出；历史评价、考勤、事件、沟通和手动档案查看保持不变。
- 课次必须属于已存在的学期；班级课次只能评价该班学生，全校课次可以覆盖所有学生。
- 班级组只能包含同一学期的班级，一个班级只能属于一个当前班级组；进度基准班必须是当前成员，但只用于形成建议。组内新建真实课次时，教师必须显式选择“按当前建议”、“指定共同讲次”或“建立独立课次”。建议只能从该班已关联的最高讲次向后推进，不自动回填更早缺口；新成员起点、倒序补建或最近一次为独立课次时，必须由教师指定。
- 共同课只能关联该组成员班级的真实课次，同一班在同一共同课下最多关联一个真实课次；共同进度不合并或转移评分、考勤、事件和反馈正文。
- 班级组管理以“共同讲次 × 当前成员班”的真实课次关系为主视图，允许把未关联课次指定到某一讲，或解除错误关联。关联或解除只改变 `GroupLessonSession`，不搬移真实课次的评分、考勤或事件。
- 共同讲次一旦关联真实课次，`sequence` 就成为历史含义并禁止修改，标题和材料草稿仍可编辑。只有没有真实课次关联、没有确认修订且没有反馈业务引用的误建草稿可删除；班级组没有任何共同讲次时才可直接删除。
- 班级后来离组或换组，不改写已经形成的共同课关系；打开历史课次时，以当时保存的 `GroupLessonSession` 还原班级组和可处理范围。已有历史关联可保持原关联或在同一历史组内调整，不得因当前成员关系变化而误挂到新组或无关组；没有历史关联的新课次才使用当前班级组。
- 共同课材料只有教师确认后的不可变修订才能供反馈批次复用；复用时复制到各班计划快照，后续修改不回写历史计划。
- 每个学期只保存一套规范化学期公共材料库；只接收 `.xlsx`，不保存原工作簿、上传路径或文件名。首次导入直接保存，已有库必须由教师明确确认后整体替换；解析失败不得改动旧库。新建共同讲次时，相同课次的课程主题、群反馈、统一测评说明、私反馈模板和材料来源会完整复制为未确认草稿，主题用作默认标题；没有同号材料则保持空白，已有讲次绝不因导入而自动覆盖。教师可以对已有讲次明确“重新套用同号材料”，已有内容时须再次确认；该操作只替换当前草稿，自动标题可随材料主题更新，教师自定义标题、确认修订、真实课次快照和计划快照不变。确认后的共同课材料才供同组课次复用。反馈准备页使用一个“本次课程材料”选择器：独立课次既可采用学期材料，也可只为当前课次保存自定义课程背景；共同课材料变更仍须显式确认共享。课程材料是可选背景，选择“不使用”或学期尚无材料库时仍可继续，且不得回退到其他公共材料。
- 默认反馈工作流既可处理一个班级，也可在所选课次已关联共同课时处理整个班级组。共同课模式只有一个投料和核对入口，服务端仍为每个真实课次保存独立 `FeedbackIntakeRun`，并为每班创建独立 `FeedbackPlan` 后由 `FeedbackPlanBatch` 编排。
- 多班录入按真实班级分别确认；某一班存在阻断异常或请求失败时，不得撤销已经确认的其他班。进入规划前，教师可以明确把未就绪班级留待后续处理，本轮只纳入已准备班级；系统不得静默排除班级，留待处理的班级仍可回到录入继续核对和重试。
- 班级组不保存第二份学生名单；本轮学生范围从各班当前 `ACTIVE` 的 `StudentClassEnrollment` 组织。助教表先按班级归属，再在该班 ACTIVE 花名册中匹配学生，最后核对当前课次；STEP 按班级和稳定身份路由。个人 PDF 可按组内花名册唯一匹配学生，再绑定该生所属的真实课次。任何重名、身份冲突或无法确定真实课次的材料都不得自动归属。
- 班级组可共享一份默认反馈要求和生成偏好；班级例外落在对应 `FeedbackPlan`，学生例外落在对应 `FeedbackPlanItem.generationConfigSnapshot`。继承只减少重复设置，不得合并学生事实、PDF 证据、正文或批准状态。
- 班级组生成按学生而不是按整班排队；各班子计划共享最多两个活动模型调用，任一学生失败不阻断其他班。全部可运行学生完成后才汇总批次失败，普通重试只重新领取各班失败条目，不改写已成功正文。
- 创建班级课次时，只为该学期当前 `ACTIVE` 归属创建初始考勤；转班不改写历史课次。
- 删除班级或学期只进入 30 天回收站，不立即改写或删除其课次、事实、计划和结果。学期进入回收站时整个所属范围不可用；恢复学期不自动恢复此前单独删除的班级。任一班级进入回收站时，包含该班的整份多班计划不可用，恢复后按原来的手动归档状态重新判定是否可见。
- 课次只允许在完全空白误建时删除。清空课次事实是独立操作：备份并校验数据库后清除当前 `SessionMetric`、`Attendance`、`Event`、`FeedbackIntakeRun`、对应录入草案和派生缓存；在 `SessionMetricHistory(changeType="clear")` 保留评价快照，且不修改沟通、公共材料、共同课关系、计划快照、正文、批准、导出和生成记录。
- 同一学生、同一课次最多一条课次评价和一条考勤。
- A/B/C 的正式写入仍经过教师发起的事实确认流程；唯一匹配个人出门测的正确率按确定性规则直接形成 A，不增加逐生或逐分批准。D 由系统计算，LLM 不直接决定 D。
- NL 录入选择班级课次后，花名册中未被提及的学生按缺勤处理。
- 统一课后材料入口先汇总候选事实和异常，教师确认后才在一个事务中应用。日期允许在当前课次年份明确时把 `8.13`、`08-13`、`2026/8/13` 等常见写法归一；明确的错班级阻断，错日期或错课次按来源一次确认。学生身份使用唯一规则：学号与姓名命中同一学生时直接匹配；无效或过期学号可降级到当前班唯一精确同名学生；学号与姓名分别指向不同学生、重名或姓名缺失时必须由教师处理。教师可以绑定当前班候选或只跳过异常行；跳过一行不得丢弃同一助教表中已经匹配的其他学生。“仍作为当前课次采用”只处理日期和课次边界，不能替代班级或学生身份确认。STEP 继续严格核对稳定 ID、姓名、班级和日期，只采用文件中明确的考勤和完整 A/B/C，不补推缺失评分，也不从未提及学生推断缺勤。唯一匹配的个人 PDF 直接按正确率换算 A；分数不一致时只挂起冲突维度，由教师在页面选择来源和值，未冲突的其他事实继续保留。
- `FeedbackIntakeRun` 的来源指纹同时包含材料清单与解析器版本：同一解析规则下重复扫描不重复写入，匹配规则修复后允许相同文件重新形成新 run。固定收件箱只在教师主动打开课后任务或点击重新扫描时读取，不持续监听、不移动或删除源文件。ZIP 仅在本次处理内解包，原始文件不落库。
- 没有上传文件时，统一课后入口可以从当前课次已经录入并确认的评价、考勤和事件建立仅含既有事实的 `FeedbackIntakeRun`；手工评分不要求再上传占位文件。若当前范围既没有可用事实也没有反馈对象，仍应明确提示，而不是创建空计划。
- 课次评价被更新或删除前，应追加 `SessionMetricHistory`，不能覆盖旧历史。
- `FeedbackTaskDraftV2` 只恢复尚未形成服务端计划前的当前标签页录入状态；计划创建后，名称、学生范围、公共材料、默认反馈策略和显式例外由 `FeedbackPlan` 或 `FeedbackPlanBatch` 草稿恢复。URL 的 `view=intake|plan|studio` 只决定正在查看哪一步，不改变计划运行状态。
- `FeedbackIntakeRun.planId` 只作为旧数据库中的历史遗留列保留；当前产品不再写入、读取或清理它，也不能用它判断是否已建立计划、录入是否可复用或当前计划身份。每份计划由自己的输入快照、录入来源摘要和请求标识记录事实关系；继续录入可以更新事实库，但不能回写已存在计划的冻结快照。
- 计划和批次使用面向教师的 `displayName` 区分；历史未命名记录按自动标题显示并可重命名。生成开始前的草稿可保存配置，生成开始后只允许改显示名称，不能原位改写生成范围或策略。
- 修正已生成计划必须创建带 `basedOnPlanId` 或 `basedOnBatchId` 的新草稿。新草稿默认复制原计划的冻结事实、范围和生成配置，但不复制正文、模型生成、批准或导出状态；若教师需要新录入事实，必须明确选择按事实库当前状态建立另一份计划。
- 工作台顶部只显示紧凑的当前计划栏；其余未归档且所属范围可用的计划和批次进入切换抽屉，批次只显示一个业务条目。当前计划、正在生成、需要继续和最近完成均由顶层状态、条目统计与历史标志确定性派生，不新增业务状态列；批准和导出继续独立表达。
- 日志、页面历史等辅助写入失败，不应把已经完成的核心业务写入显示为失败。
- WCG handoff 只有在路径、大小、Schema、SHA-256、包身份和幂等性都通过后才登记。证据日期可能同时落入多个重叠学期，系统先取覆盖全部证据日期的候选学期，再在这些学期的 `ACTIVE` 名单并集中唯一匹配学生，并以该学生唯一的学期归属确定目标学期；重叠日期本身不构成人工匹配理由。同一来源和企微会话已经由教师确认过唯一学生时，后续包可复用该映射，但仍须重新校验候选学期内的唯一归属。其余不确定项进入人工匹配或受控失败状态。
- handoff 中家长对反馈长短（包括明确表示长短均可）、文字/语音、微信电话、频率等问题的直接回答属于显式沟通偏好。提取模型必须为每个受控值引用包内 incoming 家长消息 ID 和逐字证据；老师的问题、收悉、复制模板、未回复、回复速度、语气以及普通学习描述不能形成偏好。教师确认沟通草稿后只生成待复核候选，确认候选前不影响反馈生成。
- 二次提取必须有可追溯证据，并明确属于学习进步、具体困难、学习习惯、学习方法、学习信心、家长关切、反馈偏好、教师承诺或临时学习背景之一；低价值和无关记录标记为无有效内容，不创建 `Communication`。
- handoff 包不携带 Student Track 学生 ID、课次或正式业务记录。只有教师在 `DraftRecord` 中选择实际课次并确认后，才写入正式 `Communication`。

## 暂不新增的概念

`Exam` 目前不是独立领域实体。“测验”可记录为 A 维评价的一部分或 `Event`。只有当测验具有独立名称、日期、满分、参与名单、成绩集合和修改流程时，才论证新增 `Exam`。

`Score` 也不是独立实体。代码和文档应使用“课次评价”指代 `SessionMetric`，使用“维度分数”指代其中的 A/B/C/D 字段。

## 辅助模型

`Label`、`StudentLabel` 用于学生分类；`DraftRecord`、`SystemLog` 和 `SessionMetricHistory` 支持业务流程与追踪，但不改变学生、班级、学期、课次、评价和考勤构成的核心领域。

`WeComImportState`、`WeComImportRun`、`WeComImportOperation`、
`WeComMessageReceipt` 和 `WeComImportChange` 是旧集成的只读历史账本，不是学生档案。
新代码不再活动写入、运行或回滚这些记录，本次解耦不删表、不改行。

`WeComHandoffPackage` 是 WCG 本地文件转交账本，只保存来源、包 ID、文件哈希、
处理状态和可选的匹配学生，不复制聊天正文。文件包和安全回执位于 Git 仓库外的
中立 Application Support 目录；正式沟通仍只在教师复核并绑定课次后产生。

`AI内部关注：*` 是教师内部使用的全局学生标签。已确认的课堂文字可以添加“成绩表现、学习信心、家长担心、退班意向”四类受控标签；WCG handoff 消费不创建这些标签。多个内部标签在仪表盘中只构成一个独立的“定性反馈”条件；它们不得进入家长反馈提示词、预览或导出，也不参与任何评分计算。

教学总结是实时确定性事实与可失效 AI 解读的组合视图。数字、完整度、出勤和状态变化只能由代码计算；模型不得计算或改写事实。教师沟通观察只使用已确认 `Communication`，以学生、观察类型和主题聚合。相同证据不重复创建；出现新证据时，已处理或已忽略的观察重新成为“新发现”。观察状态不修改来源沟通，也不进入学生风险、评分或对外反馈。

AI 生成历史采用三层保留：每班最近五次已完成课次保留完整的业务输入/输出快照；更早但未满六个月的记录压缩为不可全盘复原的学期快照；来源课次满六个月后只保留教师确认的长期教学背景与最小审计账本。热转温不调用模型，温转长期背景只读取已确认学期快照中的受控摘要，按班级手动批量生成草案并需要教师确认；没有可靠摘要时必须跳过。1.0 beta 的长期背景只在教师工作区内部展示，不进入家长反馈 prompt、预览、成稿或导出。原始企微聊天、模型思维内容、凭据和供应商原始协议永不写入这些表。

仪表盘的学生风险是实时派生视图，不写入数据库：前四次课以早期相对表现作为一个数字条件；第五次课起改用近期评分回落和长期低于同期班均。近期评分回落以最后 20% 有效课次和本学期个人总体平均之间的差距判定。一个独立条件显示“关注”，两个及以上显示“警告”。考勤提醒学生只在考勤区展示，不再进入上方学习风险排名；班级状态仍独立展示。

## 反馈上下文

课后反馈上下文不是新表，而是从现有领域模型临时组装出来的视图。它可以包含：

- 本课次的 `SessionMetric`、`Attendance` 和 `Event`。
- 近期若干课次的评价趋势和关键事件。
- 最近且仍有效的 `Communication`，包括企微导入的反馈上下文摘要。按实际沟通时间或跨日范围的结束时间由近到远使用，新信息覆盖旧信息；实际发生时间晚于目标课次的证据不会进入反馈 Prompt；历史噪声记录不会进入反馈 Prompt。
- 学生已有标签。

反馈上下文只服务于生成和预览，不直接写回数据库。持久化证据和教师预览保留可审计的精确日期；进入模型的上下文由程序改写成“今天、昨天、前天、更早”等相对时间，跨日范围保持为范围，成稿边界还会再次去除精确日期。若上下文中出现错误，应修正原始学生记录、课次评价、事件、沟通或标签，而不是为上下文本身新增修补字段。

反馈强度是本次生成策略，不是学生画像或新的领域状态：系统只用当前学期 Dashboard 的学习风险与目标课次前 21 天内未关闭的教师沟通观察，分为常规、轻关注和重点关注；考勤提醒不参与。常规反馈采用短、描述性的单次生成；轻关注和重点关注保留内部分析与审核。教师对本次计划的要求和选择随 `FeedbackPlan` 保存，不改变后续课次、风险或观察。内部原因、观察正文和风险标签不得进入家长话术或导出。

群反馈和统一出门测说明属于“课程公共材料”：它们只能说明本节教了什么、测了什么以及统一订正建议，不能证明某个学生已经掌握或出现错误。学期话术库按 `ClassSession.semesterNumber` 推荐课次，教师明确点击后才覆盖当前材料；全对或有误私反馈只有在该生个人出门测证据存在时才择一作为表达参考，模板中的题号、答案和完成情况仍须由个人证据替换，续班话术不导入。可一次选择本机报告文件夹：系统先用当前课次班级名单匹配文件名，提示缺少报告，忽略其他班学生和无关文件，再以最多两份并发解析。个人出门测 PDF 经本机解析后可以提供该生本次正确率、知识点和错题证据；唯一匹配时，正确率同时按确定性规则换算为本课 A。课程材料内部绑定课次，PDF 证据同时绑定课次与学生，服务端拒绝跨课次或跨学生混用。原始 PDF 不保存；提炼后的带绑定证据可以随当前反馈标签页状态或 FeedbackPlan 证据快照保存，但不成为新的考试实体。反馈计划的测评证据允许同时容纳出门测与未来的课堂练习结果，每项都必须声明来源，并继续遵守同一学生、课次和单次结果边界。

趋势表达不比较“前两次与最近两次”。最近两次有效 A 维评价同时对照该生本学期整体常态和各自课次的同期班均；个人记录不足三次或同课次有效学生不足三人时省略对应结论。对照结果用于解释近期状态，不输出排名，也不修改原始评价。

## 反馈计划

反馈计划是反馈规划、生成和反馈历史的唯一权威来源；录入事实的权威仍是正式课堂事实与 `FeedbackIntakeRun` 确认账本。`inputSnapshot` 固化创建时的课次绑定、课程材料、学生证据、录入来源摘要以及生成偏好；V2 快照可用于只读回看，历史 V1 快照按缺少来源摘要兼容。模块可以不预选，空 `moduleKeys` 表示使用当前反馈类型的完整允许目录。学生条目可在 `generationConfigSnapshot` 中保存独立的反馈类型、特殊处理要求、结尾和模块配置；空对象表示沿用批次公共配置。新计划必须显式保存 `restricted` 或 `free` 生成方式；`generationApproach = "legacy"` 只标识历史计划，禁止开始、继续或重试生成。legacy 已有正文仍可在未批准、未导出前编辑，并可继续复核、批准和导出；需要重新生成时必须另存为明确选择 `restricted` 或 `free` 的新计划。生成启动后，生成方式、审核、重试、批准和导出都遵守冻结快照；配置修订必须另建计划。`generationExecutionSnapshot` 保存条目实际请求方式、执行方式、失败、重试、受限检查点和教师确认的显式降级，刷新、暂停或进程重启不得抹掉这些状态。`archivedAt` 只隐藏计划，不抹掉已生成、批准或导出的记录；只有没有生成、批准、导出和附件的纯草稿允许删除。`GenerationRecord` 只作为跨功能模型审计账本，不作为教师日常历史入口。历史页按学期、班级、课次、学生、课程日期、状态和归档状态读取 `FeedbackPlan`。

反馈计划提供受限反馈和自由反馈。受限反馈先让 Planner 根据当前学生的冻结材料产生 `FeedbackStrategyV1`，再由服务端编译只含准许披露内容的 `RestrictedWriterInputV1`；Writer 不接触完整证据包、原始沟通、内部排除理由或其他学生信息。自由反馈由一个逻辑模型阶段直接根据当前学生的冻结、已确认材料形成结构化 Composition；结构修复可以重试，但不进入第二个审核模型。两种方式统一执行收件人、串名、证据、模块、家长动作和正文程序核验，并继续写入现有正文、批准与导出结构。受限 Writer 返回合法 JSON 和非空正文、但模块或覆盖协议仍未通过时，系统可以只提取正文保存为带硬阻断的待复核草稿；失败输出中的模块、引用和家长动作不作为可信结构，也不建立成功 `GenerationRecord`。教师必须实际修改并保存正文，由系统重新核验后才可批准或导出。受限失败的普通重试仍使用受限方式，绝不自动降级；只有教师明确确认“改用自由反馈”后，失败条目以及同批尚未开始的条目才切换实际执行方式，已成功结果、正文和审计记录保持不变。个人反馈不是固定模板：教师可以不预选模块，也可以选择当前类型允许的任意模块。表现良好可以只停在具体认可；家长动作只有真实需要时出现。

反馈计划的自然语言反馈要求统一承载原“本次目的”、输出策略和教师补充事实。教师在此输入的事实陈述直接视为已确认事实，可以补充或纠正证据篮子；发生冲突时以教师本次输入为准。模型以教师输入和未被纠正的证据事实为底座充分联想，形成原文之外的教学判断、可能原因和趋势解释，但不凭空编造两类输入都没有的具体事件、人物、分数或已发生动作。自然语言同时决定收件人、风格、篇幅、表达顺序、重点和取舍；家庭沟通偏好等内部结构化字段只在自然语言没有说明时作为默认值。模块内容来自教师补充事实时允许不填写 `evidenceRefs`，不得为了结构校验伪造证据引用。

四类计划提供默认内部结构：`class_update` 面向班级公共教学信息；`event_micro` 处理单个事件；`stage_trend` 汇总阶段起点、趋势和断点；`course_end` 总结教学和下一阶段学习路径。教师可以不选择模块，也可以选择任意数量的当前类型模块；选择结果为空时由生成模型在完整目录内自然取舍，非空时只允许使用所选模块。教师自然语言要求可以调整正文的关注点与表达方式；结构字段缺少对应证据或任务时只进入教师复核提示，不自动删除正文。教师直接修改最终文本时不再调用模型，只执行空正文、串错学生等最小程序门禁并要求重新批准。
